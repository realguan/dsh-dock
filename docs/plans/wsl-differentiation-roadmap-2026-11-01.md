# WSL 差异化功能与体验路线建议（方案稿）

> **状态：方案稿，未生效。** 只回答「WSL 还能做什么、先做什么、用户看到什么」，
> 不涉及代码改动；拍板后再拆实施项、立 ADR、进 `docs/roadmap.md` 正本。
> 撰写：2026-11-01。依据：仓库现状盘点（ADR-0004 / ADR-0010 / ADR-0016 / ADR-0035，
> v1.4.2）与现有 WSL 实现，不引用外部产品路线。

---

## 0. 结论先行

**WSL 的差异化不在「能不能跑」，而在「把它当成一个一等世界来管」。**

现状是：WSL 的能力面已经基本对齐本地档——启动、引擎自举、profile / 插件 / 会话 /
凭据 / 设置 / MCP / 诊断全部下沉客体（ADR-0004/0010/0016），连安全模式、实验能力目录、
MCP 探测、补丁写入也已补齐。**继续加「又一个 WSL 功能」的边际收益已经很低**；
真正缺的是把这个世界**显性化、可切换、可修复、可带走**。

因此建议按三句话排路线：

1. **看得见、切得动**（第一批，建议拆成 2–3 个小版本，S/M）：世界标识、发行版选择、首启引导、WSL 体检卡、一键切换；
2. **管得住、带得走**（随后 2–4 个版本，M/L）：世界快照 / 备份 / 恢复、跨世界迁移、路径 / 终端 / 端口桥；
3. **可复制、可并行**（有信号再排，L/XL）：环境蓝图、多世界并行、更新后巡检。

一句话产品命题：

> **官方 dsh 不管 WSL，纯 WSL 只有终端；dsh-dock 让 Windows 上的 Linux AI 工作台
> 可见、可控、可回滚、可复制。**

如果只选一个对外主打点：不是「能跑 WSL」（启动 / 引擎 / 管理面已经打通），而是
**「你的 WSL 工作台可以备份、搬走、复制」**——这是官方和纯 WSL 都给不了的。
H1 是让这个价值被看见的前置，H2/H3 才是护城河本身。

## 1. 现状盘点：已经走到哪，真正缺什么

### 1.1 已具备，不要重复建设

| 面 | 现状 | 依据 |
|:---|:---|:---|
| 启动 | WSL2 探测、发行版自动选择、客体启动、localhost 转发、哨兵文件就绪判定、teardown | `executor.rs`（ADR-0004） |
| 引擎 | 客体 node / pnpm / dsh 全自动补齐，与本地同源、壳管理、glibc-only | ADR-0010 |
| 管理面 | profile 全生命周期、插件装卸/启停/跨 profile、会话、凭据（0600）、dsh 设置、MCP、诊断、日志 | ADR-0016 及 P1–P3 落地记录 |
| 客体写内核 | 同一 `PatchFile` 内核 + 备份 + 原子替换；安全模式、官方插件行、实验能力目录 | ADR-0016 后续 / 2026-09-21 方案 |
| 世界感知 | `World::{Local, Wsl}` 择源、管理面读写与运行会话同源、关于页/版本/升级按世界取数 | `mgmt.rs`、`commands/update.rs` |
| 启动身份 | token 握手裁定工作台身份，修掉 WSL 启动屏静默卡死 | ADR-0035 / v1.4.2 |
| 模式偏好 | 首启选择「每次询问 / 本地 / WSL」，可持久化 `defaultMode` | `settings.rs` |

> 诚实边界：MCP 能力探测已下沉的是 **stdio** 型；`streamable-http` 型在客体档仍显式拒绝
> （url 指向客体内部地址，从宿主发是错结论，`commands/console.rs` 已注明）。这是语义边界，
> 不是平台收窄；本路线不把它当作差异化重点。

### 1.2 真正的缺口（按用户感知排序）

| # | 缺口 | 用户感受 | 现状证据 | 影响 |
|:--|:---|:---|:---|:---|
| G1 | **发行版不可选**：无 UI，自动取「默认 WSL2，否则第一个 WSL2」 | 「我装了三个发行版，为什么总是进 Ubuntu？」「怎么换？」 | `select_wsl2_distro`（`executor.rs`）；前端零 distro 概念 | 高：多发行版用户直接被挡住 |
| G2 | **主界面不知道在哪个世界**：启动屏之外没有常驻世界标识 | 「我现在管的是 Windows 的 profile，还是 WSL 里的？」 | 前端无 `world` / 常驻 `distro` 标识；只有健康大盘的 `platform.os` 串里带 `linux (WSL: …)`、以及启动页 URL 参数 | 高：管理面读写的是真世界，但用户看不见 |
| G3 | **切换入口藏在启动屏**：控制中心只能设「下次启动」 | 「想临时进 WSL 跑一下，要重启到启动屏？」 | `PreferencesPane` 仅 `defaultMode`；启动页悬浮胶囊 | 中高：切换成本高，WSL 变成一次性选择 |
| G4 | **没有 WSL 体检 / 修复面**：只有失败后的一句话错误卡 | 「到底是 WSL 没装、WSL1、还是引擎坏了？」 | 诊断只到客体 Linux 层；无 `wsl --status`、网络模式、端口、vhdx、vmmem | 高：WSL 故障是支持成本大头 |
| G5 | **世界不可备份 / 迁移**：删发行版、重装 Windows、换机器就从头来 | 「这套 profile + 插件 + MCP 能不能带走？」 | 无导出/导入原语；只有单文件 `.bak-` | 高：用户不敢投入，留存受损 |
| G6 | **路径 / 终端 / 端口摩擦**：Windows 路径与客体 `/mnt/c` 两套；端口在另一个命名空间 | 「项目在 C 盘，WSL 里怎么打开？」「端口被谁占了？」 | 无路径翻译、无终端深链、无端口面板 | 中：日常高频小摩擦 |
| G7 | **首启没有 WSL 引导**：没装 WSL / 只有 WSL1 / musl 时只有命令提示 | 「我照做了，然后呢？」 | 错误文案 + 命令；无分步引导、无重探测 | 中高：决定新用户是否进入 WSL |
| G8 | **没有多世界 / 多发行版并行** | 「本地和 WSL 能同时开吗？」 | 1:1 生命周期（ADR-0015）、单活跃会话 | 低（当前）/ 高（长期） |

### 1.3 判断

**能力已对齐，产品还没「显性化」。** 现在的 WSL 更像一条隐藏的「高级启动参数」，
而不是一个被命名、被呈现、被照顾的世界。差异化要从这里开始，而不是继续堆能力。

## 2. 差异化命题：把 WSL 做成「一等世界」

### 2.1 为什么是 dock

- **官方结构性不做**：官方桌面壳没有 WSL 概念（定位方案调研，2026-09-18），这不是排期问题；
- **纯 WSL 只有终端**：对 dsh 工作台而言，发行版、引擎、profile、插件、端口、磁盘全靠命令行和记忆；
- **dock 已经有 World seam**：管理面读写已经按世界择源，缺的只是把它产品化；
- **与现行定位不冲突**：ADR-0032 定的是「web 档套壳 + 管理面」，WSL 正是管理面的自然延伸，
  不是去冒充官方客户端，也不是改 dsh 源码。

### 2.2 三个承诺（外加一个远期）

| 承诺 | 用户话术 | 对应能力 |
|:---|:---|:---|
| **看得见** | 「我在哪个世界、用的哪个发行版、引擎什么版本，一眼就知道」 | 世界标识、世界感知文案、WSL 体检 |
| **切得动** | 「本地和 WSL 随时换，不用去找启动屏；当前 profile 能带就带，带不了明确告诉我」 | 发行版选择、控制中心切换、重启交接 |
| **带得走** | 「这个世界能备份、能恢复、能搬到新机器 / 新发行版」 | 世界快照、跨世界迁移、环境蓝图 |
| **可并行**（远期） | 「本地和 WSL 各开一个窗口，互不干扰」 | 多世界并行（依赖 A2 多开与生命周期 ADR） |

### 2.3 边界（不做什么）

- **不做 WSL 终端模拟器 / 编辑器**：深链 Windows Terminal / VS Code，别重复造轮子；
- **不自动装发行版、不提权、不改 `.wslconfig` / 网络模式**：只引导 + 给命令；
- **不静默迁移凭据**：跨世界搬运默认排除 `.credentials.yaml`，要用户显式确认；
- **不做第二套 WSL 专用 UI / 第二套文件内核**：同一管理面 + 世界上下文；
- **不解析会话内容**：仍只做元数据管理（既有不做清单）；
- **不在 WSL 上另立平台分支**：Windows 本地 / WSL 是同一产品的两种世界，不是两个产品；
- **没有 Windows 真机验证，不宣称「WSL 已适配」**：这是仓库既有诚实边界。

## 4. 第一阶段：看得见、切得动（建议拆成 2–3 个小版本）

> 目标：让 WSL 从「隐藏启动参数」变成「产品里一个有名字的世界」。
> 这一阶段全是低风险、可回退的读侧/呈现侧改动，适合先落地拿反馈。

### 4.1 世界标识（World Badge）— S

**做什么**

- 新增只读 IPC `get_active_world`：返回 `mode`、`distro`、`engine`（node/pnpm/dsh 版本）、
  `running`、`workbench_ready`（**布尔**，不返回带 token 的 URL）；WSL 模式但发行版未定时返回
  **未定**而不是回落 Local。
- 控制中心页头（新增常驻世界条）、关于页、健康大盘统一显示：
  `本地 Windows` 或 `WSL · Ubuntu-24.04`（附引擎版本）。
- 所有破坏性操作的确认文案带世界名：
  「删除 WSL（Ubuntu-24.04）中的 profile `foo`？」——不能只写「删除 profile」。
- 工作台悬浮胶囊（**若注入层能拿到世界信息**）增加一个世界色点 / 短标签（可关闭），
  让用户在主窗口也知道当前世界；拿不到就只做控制中心 / 关于页，不硬塞。

**为什么先做**

- 这是其他所有功能的地基：发行版选择、体检、备份、迁移都需要「当前世界」这个事实源；
- 成本最低、用户感知最强；同时消掉「看起来在管本地、其实在管客体」的认知风险。

**验收**

- Local / WSL 两种模式下，控制中心、关于页、健康大盘显示一致；
- 破坏性确认文案含世界名（单测钉住文案拼装纯函数）；
- WSL 但发行版未记录时显示「世界未定」+ 去选择，不显示本地数据。

### 4.2 发行版选择器 + 记忆 — M

**做什么**

- 新增只读 IPC `list_wsl_distros`：复用 `parse_wsl_list_v`，返回名称、WSL 版本、是否默认、
  运行状态（若 `wsl -l -v` 输出可解析；否则显示「未知」，不猜）；WSL1 标记「不可用（需升级 WSL2）」。
- 启动页的「WSL 模式」卡片展开为发行版列表：默认项、上次使用项、其他项；
  WSL1 置灰并给 `wsl --set-version <distro> 2` 命令；无发行版时给 `wsl --install` 引导。
- 记忆用户选择：`settings.json` 新增 `wslDistro`（**须先登记 AGENTS §6 持久化例外册**）；
  未设置时仍按「默认 WSL2 → 第一个 WSL2」兜底，但 UI 明示「自动选择」。
- 切换发行版 = 一次重启（复用 ADR-0014 交接）；明确告诉用户「将重启当前工作台，
  目标世界的 profile **建议**按同名优先、缺失回落默认档」——不承诺「profile 一定不变」
  （现状菜单/托盘的 `switch_mode` 会清掉强制目标、重走 `defaultProfile → 选择器`；
  启动页的 `choose_mode` 清理语义与之不完全一致，两条入口需要统一，见 `boot.rs`）。

**为什么**

- 这是 WSL 迭代 v2 里一直挂着的「多发行版选择 UI」（`docs/roadmap.md` 4.9），
  也是 G1 的直接解；没有它，多发行版用户永远只能用默认那个。

**验收**

- 选非默认发行版 → 重启 → 进入该发行版；重启后标识正确；
- 发行版被删除 / 改名后，启动给出「原发行版不存在，请重选」，不静默换一个；
- WSL1-only、无发行版、musl 三种情况各有明确文案与下一步；
- 非 Windows 平台零感知（命令不注册或返回空）。

### 4.3 控制中心一键切换 — S/M

**做什么**

- 控制中心「运行环境」从「下次启动」升级为「当前世界 + 切换」：
  `本地 Windows` / `WSL · Ubuntu-24.04` / `更换发行版…`。
- 切换前确认：列出将重启的会话 / 当前 profile / 目标世界是否有同名 profile；
  确认后走既有 `choose_mode` 语义，复用交接导轨与幕布，不新造一套切换流程。
- **切换语义要补一刀**：现状菜单/托盘的 `switch_mode` 清空强制目标后按
  `defaultProfile → 选择器` 重解析，启动页的 `choose_mode` 清理语义又不完全一致；
  两条入口都要统一，且当前临时切过去的 profile 不会自动带到新世界。建议：
  目标世界存在同名 profile 就带过去，否则回落默认档并在确认框里写明「目标世界没有 `foo`，
  将进入 `defaultProfile`」；不要静默换档。
- 保留「下次启动默认」独立设置，避免「临时切换」意外改默认。

**为什么**

- G3：现在切换必须回启动屏，WSL 像一次性选择；把入口放到用户本来就在的管理面，
  才会被日常使用。

**验收**

- 从控制中心切到 WSL / 切回本地，重启后状态正确、默认值不被误改；
- 有活跃会话时确认文案说清「会重启」；取消则什么都不发生。

### 4.4 WSL 首启引导 — M

**做什么**

- 一个「WSL 准备」向导（可跳过，不阻塞本地模式）：
  1. 检测：`wsl.exe` 是否存在、是否有发行版、是否 WSL2、是否 glibc；
  2. 解释：每种失败用一句人话 + 一条可复制命令（`wsl --install` /
     `wsl --set-version <d> 2` / 换发行版）；
  3. 重探测：用户装完后点「重新检测」，不要求重启应用；
  4. 完成：显示将使用的发行版与首次要下载的引擎，给「开始」。
- 不自动提权、不自动装发行版、不改系统设置；只给命令与官方链接（外链走既有白名单）。

**为什么**

- G7：当前失败只有一句话；新用户第一次接触 WSL 就卡住，后面的差异化能力都看不到。

**验收**

- 无 WSL / 无发行版 / 仅 WSL1 / musl 四条路径各有人话解释与可执行下一步；
- 重新检测能在不重启应用的情况下从不就绪变为就绪；
- 本地模式完全不受影响，向导可永久跳过。

### 4.5 WSL 体检卡 v1 + 诊断包 — M

**做什么**

- 在健康大盘增加「WSL 世界」区块（仅 WSL 模式）：
  - 发行版：名称、WSL 版本、运行状态、是否默认；
  - 引擎：客体 node / pnpm / dsh 版本与就绪状态（已有数据）；
  - 网络：工作台地址、localhost 可达性（复用既有就绪/握手判据，**不新增宿主网络面**；
    需要宿主机发起的检查必须先登记网络面）；
  - 存储：客体根分区 / `~/.dsh` 占用；Windows 侧 `ext4.vhdx` 大小（只读；定位不到就显示「未知」，
    不猜路径）；
  - 最近一次启动失败原因（若有）。
- 操作：`重启发行版`（`wsl --terminate <distro>`，先停会话、确认框写明「会停止该发行版内
  所有进程，不只 dsh」）、`重新铺设客体引擎`
  （先停会话 → 备份并改名 `~/.dsh-dock/engines` → 走既有引导，保留 `~/.dsh`）、
  `打开 WSL 终端`（深链）、`复制诊断包`（世界信息 + 体检结果 + 最近**壳日志**尾部；
  **默认不含 dsh 运行时日志**，用户勾选时先预览并脱敏）。
- 每一项都回答三件事：**是什么、为什么、下一步**；给不出下一步就不摆按钮。

**为什么**

- G4：WSL 故障是支持成本大头；ADR-0035 的静默卡死说明「全绿但其实没进去」比报错更伤；
- 「复制诊断包」能让用户一次把有效信息贴进 issue / 群，直接降低支持往返。

**验收**

- 每条检查有明确状态（通过 / 警告 / 失败）与原因；
- 「重启发行版」不会误删数据；「重铺引擎」保留 profile / 会话 / 凭据；
- 诊断包不含 token、Cookie、凭据明文；默认不含 dsh 运行时日志（可能含 prompt / 响应内容），
  复制内容可直接粘贴。

## 5. 第二阶段：管得住、带得走

> 目标：让用户敢把 WSL 当长期工作台——坏了能回滚，换机能搬走。
> 这一阶段开始出现新原语 / 新格式，**先立 ADR 再动码**。

### 5.1 世界快照 / 备份 / 恢复 — L

**做什么**

- 备份对象：客体 `~/.dsh`（profile 目录、settings、MCP 配置、插件清单、会话元数据；
  会话正文是否纳入由用户选择）+ 引擎清单（node/pnpm/dsh 版本）。**排除 `node_modules`**
  （符号链接农场，恢复时按清单重装），避免归档体积与链接语义问题。
- **凭据默认排除**；要包含必须显式勾选并二次确认（0600 / 明文风险说清楚）。
- 产物：单个归档 + manifest（版本、时间、大小、校验和、包含项），落在 Windows 用户选定目录；
  保留最近 N 份（建议 3），恢复前自动再做一份当前快照。
- 恢复：先校验 manifest / 校验和 / 引擎兼容性，再整体替换；失败可回滚到恢复前快照。
- 可选进阶：发行版级 `wsl --export/import`（更重、会停发行版，单独入口，不混进日常备份）。

**为什么**

- G5：WSL 世界最容易「一删就没」；没有快照，用户不敢装插件、不敢升级、不敢换发行版。
- 这是「可回滚」承诺的核心，也是后续迁移 / 蓝图的基础设施。

**风险与约束**

- 大文件走 9p 可能慢：归档在客体侧生成，再整包取回，避免逐文件跨边界；
- 会话内容敏感：默认只备份配置与元数据，正文单独勾选；
- 引擎版本漂移：manifest 记录版本，恢复时提示「引擎将按当前锁定版本重铺」；
- 必须复用既有文件不变量（原子替换、备份、0600），不能另写一套。

**验收**

- 备份 → 删除 / 改名 profile → 恢复 → dsh 能启动且插件列表一致；
- 恢复失败不破坏当前世界（恢复前快照可回退）；
- 诊断包 / 快照都不含明文凭据（有测试或闸门）。

### 5.2 跨世界迁移（Local ↔ WSL）— L

**做什么**

- 向导式迁移：选来源世界 → 选 profile / 插件组合 / MCP / 设置 → 预览将发生的变化 →
  执行（目标侧先备份）→ 启动冒烟。
- 规则：不复制 `node_modules`（符号链接农场），到目标侧用 pnpm 重装；
  路径引用（MCP cwd、插件本地路径）逐条列出并让用户确认；
  凭据不迁移，目标侧提示重新录入或引用。
- 双向：本地 → WSL（常见：先本地试用，后来要 Linux 工具链）；
  WSL → 本地（少见但对称，别做成单向）。
- 与「profile 模板化 + 导出/导入」（roadmap A1）共用格式，不另造一套。

**为什么**

- G5 的另一半：用户不是只想备份，而是想「把这套东西搬到另一个世界 / 另一台机器」；
- 这是竞品最难抄的部分——它依赖完整的管理面，而不是一个启动器。

**验收**

- 迁移一个带 3 个插件 + 1 个 MCP 的 profile，目标世界启动成功、插件列表一致；
- 路径类配置有明确警告，不静默改写；
- 迁移中断可回滚（目标侧预备份）。

### 5.3 路径 / 终端 / 端口桥 — M

**做什么**

- 路径翻译：`C:\work\proj` ↔ `/mnt/c/work/proj`，`\\wsl$\<distro>\home\...` ↔ 客体路径；
  在控制中心 / 复制按钮 / 路径输入处可用（纯函数 + 单测）。
- 终端深链：`在 Windows Terminal 打开此目录`（`wt.exe` 可用时），
  不可用时给 `wsl.exe -d <distro> --cd <path>` 可复制命令；不做内嵌终端。
- 端口面板：客体监听端口列表（客体侧 `ss` / `netstat` 只读采集，缺工具时降级读
  `/proc/net/tcp`）+ 工作台端口 + 「在浏览器打开」；与宿主端口冲突时给出提示（不自动改端口）。
- 性能提示：检测到项目位于 `/mnt/c/...` 时，非阻断提示「9p 跨文件系统较慢，
  建议放到客体 `~/projects`」，附「为什么」链接；不阻止、不自动搬。

**为什么**

- G6：这些是每天都会遇到的小摩擦，单个成本低、感知强，能把「能用」变成「顺手」。

**边界**

- 端口采集在客体内部完成，避免宿主新增网络面；若必须从宿主探测，先登记；
- 终端 / 编辑器只做深链，不接管用户工具链。

**验收**

- 路径翻译覆盖盘符、反斜杠、`\\wsl$`、大小写与空格；反例（`..`、UNC 其他主机）拒绝；
- 端口面板能列出工作台端口并打开；冲突提示可操作；
- `/mnt/c` 提示可关闭且不重复打扰。

### 5.4 客体引擎修复 / 重装 — M

**做什么**

- 体检卡里的「重新铺设客体引擎」：确认后删除客体 `~/.dsh-dock/engines`，
  走既有 `ensure_guest_engine` 重新引导；不动 `~/.dsh`。
- 显示修复进度与失败原因；失败保留旧引擎目录（先改名而不是直接删），可回退。
- 可选「校验引擎完整性」：版本 / 可执行 / 权限检查。

**为什么**

- 引擎坏了现在只能删发行版或手敲命令；这是「可修复」承诺的最后一公里。

**验收**

- 人为破坏客体引擎 → 修复 → 工作台能启动；
- 修复失败不丢 profile / 会话；有明确的下一条命令。

## 6. 第三阶段：可复制、可并行（有信号再排）

### 6.1 环境蓝图（World Blueprint）— L

- 一份声明式文件：引擎版本 + profile 列表 + 插件/版本 + MCP 配置 + settings（脱敏），
  **不含凭据**；可在新发行版 / 新机器 / 团队间复制。
- 应用 = 建 profile → 装插件（复用转发链）→ 写配置（同一 PatchFile 内核）→ 启动冒烟。
- 与 A1（profile 模板化 + 导出/导入）共用格式；区别是蓝图还锁引擎版本与 MCP。
- 这是长期最强的差异化：用户投入越多，越离不开「可复制」。
- 风险：dsh 版本耦合、插件二进制兼容、凭据边界；需要格式 ADR 与版本迁移策略。

### 6.2 多世界并行 — XL

- 本地 + WSL，或两个发行版，各自一个窗口 / 会话；端口协调、生命周期、存储并发。
- 依赖 A2（多开并行）与 ADR-0015（1:1 生命周期）修订；先做 spike（双实例并发写
  `~/.dsh/storages` 的竞态），不要直接上。
- 不建议现在做：当前单世界已经能覆盖大多数场景，过早投入会摊薄 H1/H2 的体验。

### 6.3 更新后巡检 — M

- Windows 更新 / WSL 升级 / dsh 升级后，自动跑一次体检 + 启动冒烟；
  发现异常给「修复建议」而不是静默失败。
- 只做本地检查，不上报；结果进体检卡历史。

## 7. 体验设计细则：用户到底看到什么

### 7.1 启动页

- 两张卡片的副文案从「功能描述」改成「**将发生什么**」：
  - 本地：「使用 Windows 已就绪的引擎，零额外配置」；
  - WSL：「将使用 Ubuntu-24.04（默认）· 首次需在客体内补齐引擎」+「更换」。
- WSL 卡展开后是发行版列表，不是只有一张卡；WSL1 置灰并说明原因。
- 预检状态用三个小 chip：`WSL2 ✓` / `发行版 ✓` / `引擎待补齐`——让用户知道下一步等什么。

### 7.2 控制中心

- 顶部常驻「当前世界」条：`本地 Windows` 或 `WSL · Ubuntu-24.04` + 引擎版本 + 切换。
- 健康大盘在 WSL 模式下多一个「WSL 世界」区块（见 4.5），不是另开一页。
- 「运行环境」偏好保留「下次启动默认」，与「立即切换」分开，避免误改默认。

### 7.3 切换

- 确认文案必须回答：切到哪、会重启什么、当前 profile 能否保留（不能则说明将进入哪个档）、
  数据在哪个世界。
- 复用既有交接导轨 / 幕布 / 计时，不新造「WSL 专用」切换动画。
- 切换失败留在原世界，错误卡给「重试 / 切回 / 复制诊断」，不静默回落。

### 7.4 错误与修复

- 统一三段式：**发生了什么 → 为什么 → 一个下一步**；禁止死路重试。
- 本地模式符号链接失败时，继续保留「改用 WSL 模式」出路（已有），
  并在 WSL 不可用时给出「先安装 WSL」引导而不是同一句话。
- 每个 WSL 错误都带「复制诊断」；诊断包含世界信息，不含 token / Cookie / 凭据。

### 7.5 危险操作

- 删除 profile / 恢复快照 / 重铺引擎 / 切换发行版：确认框必须带世界名与路径；
- 恢复 / 迁移前自动预备份；失败可回退；
- 不提供「一键清空 WSL 数据」这类不可逆入口。

### 7.6 文案与命名

- 用户界面统一说「**WSL 环境 / Linux 世界**」，不暴露「客体」「世界择源」等内部术语；
- 发行版名称原样显示（`Ubuntu-24.04`），不翻译、不缩写；
- 错误文案给命令时用代码样式，方便复制。

### 7.7 性能诚实

- `/mnt/c` 项目路径提示「跨文件系统较慢」，给「移到 `~/projects`」建议，不强制；
- 客体磁盘 / vhdx 增长在体检卡可见；不在后台自动压缩（需要停发行版，必须用户确认）。

### 7.8 安静的默认

- 世界标识是常驻事实，不是每次启动弹窗；
- 体检异常才提醒；同问题不重复打扰（沿用仓库既有「同键不再弹」纪律）；
- 不新增后台遥测；反馈走「复制诊断 + GitHub issue」或用户主动点击的问卷链接。

## 8. 优先级、依赖与落地顺序

### 8.1 建议的 Now / Next / Later

| 顺序 | 项 | 理由 | 前置 |
|:---|:---|:---|:---|
| **Now 1** | 世界标识 `get_active_world` | 一切的地基；成本最低；消歧义 | 无 |
| **Now 2** | 发行版选择器 + `wslDistro` 持久化 | 多发行版刚需；补 4.9 欠账 | 设置例外登记；切换语义 |
| **Now 3** | 控制中心一键切换 | 让 WSL 进入日常路径 | Now 1/2 |
| **Now 4** | WSL 体检卡 v1 + 诊断包 | 降支持成本；建立信任 | 只读探测 |
| **Now 5** | 首启引导 | 扩大 WSL 进入面 | Now 2/4 的探测复用 |
| **Next 1** | 世界快照 / 备份 / 恢复 | 「可回滚」承诺；留存 | 新原语 + 格式 ADR |
| **Next 2** | 跨世界迁移 | 「带得走」承诺；强差异 | 快照 + A1 格式 |
| **Next 3** | 路径 / 终端 / 端口桥 | 日常顺手 | 深链 + 端口采集 |
| **Next 4** | 引擎修复 / 重装 | 可修复闭环 | 体检卡 |
| **Later 1** | 环境蓝图 | 长期护城河 | A1 |
| **Later 2** | 多世界并行 | 定位级能力 | A2 + ADR-0015 修订 |
| **Later 3** | 更新后巡检 | 稳定性 | 体检卡 |

### 8.2 工程影响面（拍板后拆）

- **IPC**：`get_active_world`、`list_wsl_distros`、`get_wsl_health`、`set_wsl_distro`、
  备份 / 恢复 / 迁移 / 端口等命令——每一条都要走 `ipc.rs::COMMANDS` + AGENTS §7 登记 +
  `lib.rs` handler + `capabilities/default.json` 三处同步（机器闸门会拦）。
- **持久化**：`wslDistro` 进 `settings.json` 前必须登记 AGENTS §6 例外册；
  快照 manifest 属于用户目录产物，不是壳状态，需在计划中说明生命周期。
- **进程**：所有 `wsl.exe` / `wt.exe` / 终端深链 spawn 必须经 `lifecycle::{spawn,run}`；
  不允许裸 `Command`。
- **网络**：默认只在客体内部探测；宿主侧任何新回环检查必须先登记网络面与
  `network_gate::EXEMPTIONS`，不得顺手加。
- **ADR**：建议新立一份「WSL 世界模型」ADR（发行版选择 / 持久化 / 切换语义 /
  多世界预留），快照格式与迁移规则再各立一份；不要在实现里夹带未裁定的产品语义。

### 8.3 验证与度量

- **真机门槛**：WSL 行为只能在 Windows + WSL2 实机验收；CI 三平台只能保编译与纯逻辑。
  每个 Now 项都要扩 `docs/executor.md` 的验证清单，状态写「已实现（待 Windows 真机验收）」，
  不写「已适配」。
- **可观察信号**（不新增遥测）：
  - GitHub issue / 群反馈中 WSL 相关占比与类型（启动 / 切换 / 引擎 / 备份）；
  - 「复制诊断包」的使用与附带信息完整度；
  - 发布后 WSL 模式相关回归缺陷数、切换失败在诊断包中的记录；
  - 若做问卷，只在用户主动点击时打开，且不自动上传。
- **投资闸门**：H1 落地后看 4–6 周信号；若 WSL 相关反馈仍集中在「启动失败」，
  优先补体检/引导而不是上快照；若出现「换机 / 多发行版 / 备份」诉求，再进 H2。

### 8.4 风险清单

| 风险 | 影响 | 缓解 |
|:---|:---|:---|
| WSL 网络模式随版本/配置变化（NAT / mirrored 等） | localhost 假设失效 | 体检卡显式检测并解释；保留「切回本地 / 用浏览器打开」逃生口 |
| WSL1 / musl / 非 glibc 发行版 | 无法运行 | 探测即明确拒绝 + 升级/换发行版命令，不静默降级 |
| Windows 更新重置默认发行版 / WSL 版本 | 启动进错世界 | 记忆选择 + 启动前校验；不存在则让用户重选 |
| `ext4.vhdx` 只增不减 / vmmem 内存 | 磁盘与内存压力 | 体检卡可见 + 给压缩/关机建议，不自动执行 |
| 9p `/mnt/c` 性能 | 工作台卡顿 | 非阻断提示 + 迁移建议，不强制 |
| 备份含凭据 / 会话正文 | 隐私泄露 | 默认排除；显式勾选 + 二次确认；诊断包脱敏 |
| 诊断包含 prompt / PII | 隐私泄露 | 默认只带壳日志；运行时日志需勾选 + 预览 + 脱敏 |
| 每条 WSL 功能都增加真机验证面 | 维护成本 | 控制 H1 范围；复用同一体检/诊断通道；CI 只保纯逻辑 |
| 过度投入而需求不足 | 机会成本 | H1 后设投资闸门；先把「可见/可选/可修」做扎实 |

3. **拆 ticket**：按 4.1 → 4.2 → 4.3 → 4.5 → 4.4 顺序，每条带纯函数测试与
   Windows 真机验收清单；4.5 的探测尽量合并为一次 `wsl.exe` 往返。
4. **先做「世界标识」**：它不改任何行为，却能立刻让 WSL 从「隐藏参数」变成「产品一等公民」，
   也是后续所有功能的公共底座。
5. **发布后看信号**：WSL 相关 issue 类型、诊断包使用、诊断包里的切换失败记录；
   4–6 周后再决定是否进 H2。
