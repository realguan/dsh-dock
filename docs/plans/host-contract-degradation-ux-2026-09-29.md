## 0. 结论先行

1. **降级不是故障，是状态。** 工作台、会话、插件、快捷键配置全部正常，只有窗口外观回退。
   因此它**不得**长成错误弹窗，**不得**并入 `BootFailure` 六分类
   （[ADR-0012](../adr/0012-typed-boot-failure.md) §2 已把该模块边界限定在 boot 失败路径）。
2. **第一次必须说清楚，之后不许再吵。** 首次判负提示一次，随即收为常驻状态点；
   同键（dsh 版本 × 壳契约代次）不再弹。对齐通知设计稿对 N7 的判据原话——
   *"否则每次开机都弹一次，三次之后用户就会把权限关掉"*。
3. **每个状态都必须给出一个真的有用的下一步；给不出就不摆假按钮。**
   主按钮优先「检查 DSH Dock 更新」，因为绝大多数情况下能让外观恢复的是**壳的新版本**，
   而不是重试（重试只会以同样方式再失败一次）。
4. **恢复必须主动、必须告知。** 壳更新后适配了该 dsh 版本 ⇒ 自动重跑金丝雀 ⇒
   通过则恢复沉浸式并提示「已恢复」。没有这一条，用户会永远以为自己还坏着。

## 1. 曝光矩阵（用户什么时候会看到什么）

| 状态 | 主窗口（工作台内） | 控制中心 / 关于 | 系统通知 |
|:--|:--|:--|:--|
| 版本已验证 | 无 | 状态：沉浸式 | 无 |
| 金丝雀**通过** | **无**（幕布后多几十毫秒） | 状态：沉浸式 | 无 |
| 金丝雀**判负**（首次） | 展开态提示一次 → 12s 后收为状态点 | 状态：安全外观 + 原因 | 主窗口失焦时发一条 |
| 已判负版本再启动 | 仅状态点 | 同上 | 无（同键不再打扰） |
| 壳更新后转为支持 | 「已恢复」提示一次（6s 自动消失） | 状态：沉浸式 | 无 |
| 用户强制启用后失败 | 展开态提示（含「已按你的确认回退」） | 状态：安全外观（用户强制过） | 无 |

**关键判断：唯一需要打扰用户的是「金丝雀首次判负」这一次。** 其余全是静默或常驻可查。

## 2. 三个曝光面

### 面 1 · 工作台内（首次主通道）

**为什么在这里**：主窗口一旦导航到工作台，壳自己的 React UI 根本不在屏幕上。
注入层是壳在工作台文档里**唯一的发声通道**——这也是
[ADR-0029](../adr/0029-immersive-titlebar-marker-injection.md) 已经确立的事实。

**形态**：与 [`switcher.js`](../../frontend/src/injected/switcher.js) **同族**——
同一个 Shadow DOM 纪律（样式不外泄、不被 dsh 样式污染）、同一个工作台 origin 门
（`switcher.js:60-63` 的判定）、同一套视觉语言（26px 磨砂药丸 / 同 token）。

- **展开态**：一次性展开成一条窄提示（宽 ≈ 420px），**12 秒后自动收起**
- **收起态**：状态点常驻在壳胶囊旁；点击可重新展开
- 胶囊被关闭时（`showFloatingSwitcher=false`）：提示以**独立药丸**形式出现一次，
  之后只在控制中心可见——**不因为用户关了胶囊就静默降级**（红线 3）

### 面 2 · 控制中心 / 关于（常驻可查）

控制中心窗口（`label=profiles`）加一行「外观」，关于弹窗加一条。
职责：**几周后回来看也知道发生过什么、为什么、还能做什么**。
这是「不再打扰」的前提——不打扰的前提是查得到。

### 面 3 · 系统通知（人不在电脑前）

归通知设计稿的**「知情即可」档**（不是 N1–N6 的"必须打扰"档），默认开、可关。

- 仅在**主窗口失焦**时发（用户盯着屏幕时不重复打扰）
- 复用既有 `dismissedUpdate` 语义做「同键不再弹」
- 点击 → `bring_to_front` 聚焦主窗口并展开面 1 的提示

## 3. 文案（全部，进 `content/zh-CN.ts`）

### 3.1 首次判负（面 1 展开态）

```
窗口顶栏已回退为系统样式
dsh 0.2.0-rc.2 的桌面外观尚未通过兼容校验。所有功能正常，仅顶栏外观不同。
[ 检查 DSH Dock 更新 ]  [ 详情 ]  [ 知道了 ]
```

三个刻意的选择：

| 选择 | 理由 |
|:--|:--|
| 标题描述**用户看到的现象**（"顶栏变了"），不写内部原因（"宿主契约未被消费"） | 用户的第一反应是"我的顶栏怎么变了"——先回答这个 |
| 第二句**立刻消除焦虑**，且「所有功能正常」在视觉上加重 | 这是整条提示最重要的一句 |
| 主按钮是**检查更新**而非**重试** | 让外观恢复的通常是壳的新版本；重试只会以同样方式再失败 |

**按钮必须诚实**：只有在**确实检测到可用更新**时才显示「检查 DSH Dock 更新」；
否则显示 `[ 重试 ]`。不摆一个点了没用的按钮。

### 3.2 收起态（状态点）

```
ⓘ   hover：安全外观（dsh 0.2.0-rc.2 待适配）
```

### 3.3 恢复态（壳更新后自动复位）

```
沉浸式顶栏已恢复
DSH Dock 已适配 dsh 0.2.0-rc.2。
[ 查看详情 ]
```

**6 秒自动消失**（好消息不需要停留）。这条必须存在——否则用户永远不知道已经好了。

### 3.4 详情面板

```
外观状态      安全模式（系统顶栏）
dsh 版本      0.2.0-rc.2
失败判据      宿主契约未被消费：shortcuts.get 在启动后 8000ms 内未被调用
发生时间      2026-09-29 15:42
尝试次数      1（本次判负后不再自动重试）
影响范围      仅窗口外观；工作台、会话、插件、快捷键配置全部正常

可以做的事
  · 更新 DSH Dock —— 新版本可能已适配
  · 重试一次
  · 复制诊断信息
  · 强制启用沉浸式外观（进阶）
```

**「失败判据」写机器判据，不写自然语言总结。** 理由与
[ADR-0012](../adr/0012-typed-boot-failure.md) 的教训同源——*措辞即契约*：
写自然语言，上游或我们自己改一句文案就会失真；写机器判据，贴进 issue 就是证据。

### 3.5 进阶：强制启用（在详情内，不进主提示）

点击后**必须有一次具名后果的确认**（不得静默执行）：

```
强制启用沉浸式顶栏？
dsh 0.2.0-rc.2 未通过宿主契约校验。强制启用可能导致工作台无法启动，
届时你会看到「Failed to load plugins」并且需要回退。
仅在你清楚后果时使用。
[ 取消 ]  [ 仍然启用 ]
```

强制启用后若启动失败 ⇒ 自动回滚，并把该版本记为**用户确认过的已拒版本**，
不再重复询问（也不再重复打扰）。

### 3.6 用户强制启用后失败的提示（面 1）

```
已按你的确认回退为系统顶栏
dsh 0.2.0-rc.2 强制启用后工作台未能启动，已自动回退。功能正常。
[ 详情 ]  [ 知道了 ]
```

## 5. 记忆与状态

### 5.1 记忆三元组

```
hostContract: {
  mode,                                  // Desktop | Canary | Safe
  verified:  [ {engine, dshVersion, contractGen} … ],
  rejected:  [ {engine, dshVersion, contractGen, reason, at, attempts, userForced} … ],
  dismissed: [ "<dshVersion>@<contractGen>" … ]
}
```

**三维缺一不可**：

- **engine**（宿主 / WSL 客体）：两者可以是**不同 dsh 版本**（台账复现点 22 已记该探测缺口），
  不得共用一份裁决；
- **dshVersion**：契约随 dsh 版本变化；
- **contractGen**（壳契约代次）：**没有这一维，`rejected` 就是永久判决**——
  壳升级后明明已适配，用户却永远卡在降级。这是最容易漏、后果最重的一维。

### 5.2 打扰预算

- 首次判负：提示 1 次（展开态）+ 失焦时 1 条系统通知
- 之后：仅状态点；**除非** ①壳契约代次变化 ②用户手动重试 ③用户强制启用后失败
- 忽略键 = `<dshVersion>@<contractGen>`，复用 `dismissedUpdate` 的「同键不再弹」语义，
  **不新造一套忽略机制**

### 5.3 持久化登记

`hostContract` 是新的运行时持久化字段 ⇒ 按 AGENTS §6 **先登记再实现**
（与 `dismissedUpdate` / `probe-cache.json` 同册）。`sessionStorage` 只用于同一次会话内
重载的档位裁决，不入册。

## 6. 类型化（对齐 ADR-0012）

```rust
enum HostContractMode { Desktop, Canary, Safe }

enum DegradeReason {                       // tagged enum，禁字符串匹配
    BridgeNotConsumed { probe: String, budget_ms: u64 },
    BootDiagnosticsNonEmpty { entries: u32 },
    MarkerClobbered,
    ProbeTimeout,
    ForcedByUser { user_confirmed: bool },
}
```

新增失败模式会触发 `match` 穷尽编译错误——与 `BootFailure` 同一手法，
让「新增失败模式」无法静默溜过（ADR-0012 的核心教训）。

## 7. 边界（明确不做什么）

| 不做 | 理由 |
|:--|:--|
| 模态对话框 | 降级不阻断任何操作 |
| 改窗口标题（塞状态进去） | AGENTS 已裁定标题供窗口切换器/任务栏/关于使用 |
| 自动上报诊断 | 诊断信息只在用户点「复制」时离开本机 |
| 猜「用户不需要知道」 | 红线 3 禁静默降级——哪怕只影响外观 |
| 启动路径上同步等待 | 探针有预算（默认 8000ms），超时按判负处理且**不拖延启动** |
| 在 main 窗口未聚焦时展开面 1 | 那条走系统通知；两条通道不重复打扰 |
