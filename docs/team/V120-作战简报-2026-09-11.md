### 1.1 订正记录：D4 初判错误（Lead 认错，2026-09-11）

Lead 初版简报称 `ShellState::boot_error`「只写不读不重置、`choose_mode` 都不清」——**该判断错误**。
**由 qa-verify（task-48）与 docs-contract（task-47）各自独立复核后指出，Lead 已亲自复验确认**：

```console
$ grep -rn "clear_boot_cache" src-tauri/src/
src-tauri/src/boot.rs:173            pub(crate) fn clear_boot_cache(&self) {   ← 首个动作就是 *err = None
src-tauri/src/boot.rs:741            lib_boot_again 内调用
src-tauri/src/boot.rs:768            switch_mode 内调用
src-tauri/src/commands/boot.rs:91    choose_mode 内调用（且在失败路径之前）
$ sed -n '44,46p' src-tauri/src/commands/boot.rs   → get_boot_status 确实读 boot_error（我原说"不读"也错）
```

**真实缺口（订正后的口径）**：

1. **主因（前端，D4 归属改为 T-F 为主）**：`bootStore.error` **无「新一轮启动开始」清零点**。
   用户实际路径是 WSL 悬浮胶囊 → `api.chooseMode(target, false)`（`BootIndex.tsx:187-211`）→ **SPA 原地调用、document 不重载** → 同一个 store 实例存活、`error` 无人清理。
   全仓 `clearError()` 只有两个调用点（ErrorCard 的重新选择、`BootIndex` 的 `onReselect`），**模式切换路径上没有**。
   对照：托盘 `switch_mode`（`boot.rs:781`）与重启/交接路径都会 `window.navigate` → store 重建 → **自愈**。这解释了「为什么只有这条路径可见」。
2. **次因（后端 seam 未收口）**：`begin_boot()` 注释自称「所有启动路径的唯一入口」（`boot.rs:181`），却**不含清缓存**；
   7 处 `begin_boot()` 调用点只有 3 处另行清缓存。漏掉的 2 处：
   - 崩溃自动拉起（`boot.rs:531`）——**恰好是「重启dsh那里可以正常收起详情」那条路径**，它不清；
   - profile 选择器 `select_profile_from_selector`（`commands/boot.rs:29`）——不清。

   ⇒ 这两条路径会在 `boot_error` 缓存里留旧错，随后**任何整文档重载都会经 `getBootStatus` 把旧错补水进新文档**（`BootIndex.tsx:95-98` 只读不判新旧）。这是前端那条之外的独立缺陷。

**结论：不要用「清后端缓存」修本条**（切模式路径上已经清了，会空转）；两处都要动，且归属分开：
后端 = seam 收口（把清缓存并入 `begin_boot()`，消灭「7 处调用 3 处清」的漂移）；前端 = 新一轮开始时清 store。

## 2. 各任务根因证据锚（供复现先行）

### T-D1 引擎全局安装（关键证据已由 Lead 取得）

- 报错文案模板在**随壳内置的 pnpm 二进制**内：`strings src-tauri/resources/pnpm/darwin-arm64.tgz 解包后 package/pnpm | grep "global package install"` →
  `$restore global package hash link at ` / `#remove global package hash link at ` / `-link the global package install directory at `。内置版本 = **pnpm 12.3.1**（`package/package.json`）。
- 本机（macOS）**实证该链接是符号链接**：
  ```
  engines/global/v11/4daac8d2…c7547 -> cfb2-18d426bbc0aba9e8-0     # 符号链接 → 真实安装目录
  engines/global/v11/cfb2-18d426bbc0aba9e8-0/                      # node_modules / package.json / pnpm-lock.yaml / pnpm-workspace.yaml
  ```
  即 pnpm 用「global package hash link」把同一份全局安装复用给不同 PNPM_HOME —— macOS 无感，Windows 需 `SeCreateSymbolicLinkPrivilege`。
- 我们已有的免链接修复**只覆盖了 project 侧**：`nodeLinker: hoisted` 写进 `engines/pnpm-workspace.yaml`（`engines.rs:1290-1294` 有测试钉住）——它解释了 ① 图里 node 这一环为何**通过**（v1.1.0 的 1.2 已修），但**管不到 global hash link**。
- 上游线索（待核）：[pnpm#13694 `Failed to create symlink (os error 1314) & Access is denied (os error 5)`](https://github.com/pnpm/pnpm/issues/13694)、[pnpm#14349 `hoisted` + `failed to rename staging directory`](https://github.com/pnpm/pnpm/issues/14349)。本会话 web_fetch 被判非公网 IP，未能读正文——请用 web_search/任何可用通道取结论。
- **不接受把「开启 Windows 开发者模式」当唯一答案**：需先确认是否存在配置/环境变量能绕开该 hash link（例如把全局安装落到 project 形态、`--config.global-dir`/`node-linker`/`package-import-method` 组合）。若确实只能改架构（不再 `pnpm add -g`，改 project 内安装 + 自建 shim），**先出 ADR 修订提案交 Lead，不得直接改**（AGENTS §9）。
- **无论上游结论如何，两件事必须做**：①错误分类拆开（网络类 vs 特权类，各自给可行动文案）；②错误卡给出可行动出路（例如「改用 WSL 模式打开」——正好与 D3 呼应）。

## 3. 协议（与既有团队口径一致，违反即返工）

1. **单写者**：只改自己任务的 write scope。跨域改动 = 停下问 Lead（AGENTS §8.1）。
2. **禁 git 写**：共享 worktree，提交由 Lead 统一做（禁止 `git add/commit/stash/checkout/restore`；只读 `git diff/log/status` 可以）。
3. **复现先行**：先让目标断言**红**（并报告**哪条断言**红了，不是只报 EXIT），再修；修完恢复现场须 **byte-exact**（sha256 比对），残留扫描 `grep -cE 'zz_|MUTATION|QA 注入'` = 0。
4. **证据落盘**：结论落 `docs/team/`（本简报指定文件名），聊天消息不算证据（M2）。
5. **闸门**（各人自跑，逐条独立执行、各自报 exit code，禁 `&&` 串联）：
   - Rust：`cd src-tauri && cargo fmt --check` / `cargo clippy --all-targets -- -D warnings` / `cargo test`
   - 前端：`cd frontend && pnpm run typecheck` / `pnpm run lint` / `pnpm run test`
   - 发版辅助脚本：`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts/tests -p 'test_*.py'`
6. **报告格式**：`任务号 | 状态 | 改动文件 | 复现锚（红→绿）| 闸门 exit code | 未决/风险`。
7. **不许"顺手"**：发现邻近问题记入你的证据文件「顺带发现」段，交 Lead 决定，不擅自扩大改动面。
