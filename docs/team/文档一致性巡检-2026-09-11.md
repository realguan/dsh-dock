## 2. 网络面（§7 L174-187）—— **本轮最重要发现**

### 2.1 唯一网络面断言（对应摘要 #3）

**断言**：§7 L174「**唯一网络面 = `updates.rs`**；其余模块禁触网，新网络需求先在此登记」，
与 ADR-0006 §2「壳运行时网络面只在 `updates.rs`——其余模块不得触网，新网络面须先在 §7 登记」。

**实测命令**：

```bash
grep -rn "ureq::" src-tauri/src/*.rs
git log --format='%h %ad %s' --date=short -S'authenticate_workbench_session' -- src-tauri/src/lib.rs src-tauri/src/boot.rs
grep -rn "authenticate_workbench_session" docs/ AGENTS.md
```

**实测输出**：

```text
src-tauri/src/boot.rs:369:    let resp = ureq::builder()
src-tauri/src/boot.rs:378:        Err(ureq::Error::Status(_, r)) => r.header("set-cookie")...
src-tauri/src/plugins.rs:204:    let resp = ureq::post(&url)
src-tauri/src/updates.rs:411/418: struct UreqGet / ureq::AgentBuilder::new()
```

`boot.rs::authenticate_workbench_session`（L361-405）= 对 dsh 报告的工作台地址发
**HTTP GET**（`ureq`，`redirects(0)`，5s 超时，仅在 URL 带 `token=` 时触发），
用于把 launch token 兑成会话 Cookie 再注入 WebView。功能于 2026-09-04 广播
（`docs/broadcasts.md` L675-685）、随 `9935cdd`（2026-09-05，注记「同批含先前在途 boot 改动」）
入库，`f5c4e55`（2026-09-08）拆模块时迁入 `boot.rs`。

**证据缺口核查（已做，非推断）**：`grep` 全仓 `docs/` 与 `AGENTS.md`，
该调用**未**出现在 §7 任何一行「已登记用途」里；2026-09-04 宪法级广播
（`docs/broadcasts.md` L675-685）自述的宪法触动项只有一条——
「`AGENTS.md` §7 增加 `get_boot_status` IPC 登记」，未含网络面登记。
即：**登记缺失是事实，不是措辞之争**。

**判定**：❌ **不一致**（按 ADR-0006 §2 字面）。除非 lead 认定「本机回环 token 兑换」
属豁免——但**豁免本身也须落盘**，否则 §7 的「其余模块禁触网」不可执行。

**影响面**：① 审计纪律——§7 是安全边界登记册，"其它模块禁触网"是唯一可审计的硬口径，
有先例破口后新增外呼无从判越界；② 附带观察（不额外定罪）：该 GET 的目标 host
未做回环校验（L391 仅在 Cookie domain 缺 host 时兜底 `127.0.0.1`），
目标直接取自 dsh 报告地址，属可收窄的加固点。

**建议动作**（最小，二选一，须 lead 裁定）：
- **A（推荐，最省）**：§7「已登记用途」补一行——
  「**工作台 Token 回环兑换**（`boot.rs::authenticate_workbench_session`，
  GET 工作台地址、`redirects(0)`、5s 超时、仅带 `launch token` 时触发——2026-09-04 落地，
  2026-09-11 补登记）」；
- **B**：若认定应回归「唯一网络面」，则由 `rust-core` 把该 HTTP 调用下沉到 `updates.rs`
  的 `HttpGet` seam（已有可注入抽象，L411-425），`boot.rs` 只留编排——这是代码改动，需排期。

### 2.2 已登记用途的完整性（对应摘要 #4）

**断言**：§7 L175-187 列出全部「已登记用途」。

**实测**：实际出网点共 5 类，§7 覆盖 3 类：

| 出网路径 | 位置 | §7 登记 |
| :-- | :-- | :-- |
| 插件运行态回环只读查询 | `plugins.rs:199-215`（2s 超时） | ✅ 已登记 |
| 插件更新检查 / 市场 Registry / dsh 版本 | `updates.rs` | ✅ 已登记 |

**建议动作**：§7 该段补一句「**客户端自更新**：`updates.rs::APP_RELEASE_FEED`

## 3. 目录与陷阱（§2 L46-56）

| 断言 | 实测命令 | 实测结果 | 判定 |
| :-- | :-- | :-- | :-- |
| `resources/dsh-snapshot/` 永不入库 | `git ls-files src-tauri/resources/dsh-snapshot` | 仅 `.gitkeep`（0 字节占位） | ✅ 一致（内容确未入库） |

| `resources/pnpm/` 永不入库 | `git ls-files src-tauri/resources/pnpm` | 空 | ✅ 一致 |
| 同上，忽略规则 | `git check-ignore -v …` | `.gitignore:11` | ✅ 一致 |
| `frontend/node-map/node-map-private.key` 永不入库 | `git ls-files frontend/node-map/` | 空 | ✅ 一致 |
| 同上，忽略规则 | `git check-ignore -v …` | `.gitignore:18` `node-map-private.key` | ✅ 一致（CONTRIBUTING §8 红线同口径） |
| §2 L52「**main.rs 6 行**勿动」 | `wc -l src-tauri/src/main.rs`；`grep -c . …` | **7 / 6** | ❌ **不一致**（字面） |

**#8 说明**：`main.rs` 逐行实测 = 2 行注释（Windows 无控制台说明）+ 1 行 `#![cfg_attr(… windows_subsystem)]`
+ 1 个空行（L4）+ 3 行 `fn main() { dsh_dock_lib::run(); }`，
即 **6 个有效行 + 1 空行 = 7 物理行**（`wc -l` = 7，`grep -c .` = 6）。
任何用 `wc -l` 做漂移检测的人/AI 都会读到 7 ≠ 6 而误判「被改过」。

**建议动作**（措辞级，最小）：§2 L52 改为「**main.rs 保持 6 行有效代码
（当前 7 物理行含 1 空行）；只调 `dsh_dock_lib::run()`**」。
影响面：零功能影响，仅消除机器判据的假阳性。

## 4. 持久化例外册（§6 L113-126）—— 附带巡检项

**断言**：§6「运行时持久化例外册（新增字段须先在此登记）」。

**实测**：`ShellSettings`（`settings.rs:40-59`）共 **7** 个字段——
`default_mode` / `default_profile` / `locale` / `auto_restart` / `show_floating_switcher` /
`switcher_shortcut` / `dismissed_update`；§6 登记项逐一对应，**无未登记字段、无僵尸登记**。
非 settings 类登记项亦核实存在：`probe-cache.json`（`resolve.rs:493`）、
`engines/`（`resolve.rs:322`）、`~/.dsh-dock-dev`（`resolve.rs:121-129`）、
`~/.dsh-dock-test`（`resolve.rs:101`）。**判定**：✅ 一致（实测）。

**无法判定项**：`app_data` 下另有 `procs/`（`lifecycle.rs:75`）、
`runtimes/fallback-home`（`resolve.rs:408`）与若干 `*.log` 落盘物，§6 未登记。
它们属运行期租约/日志而非用户可感知持久态——但 §6 未定义例外册的**准入范围**
（「设置字段」还是「一切 app_data 落盘物」），故不判不一致（见 §8 未决 2）。

   ADR / 广播条目（已 grep `docs/` 与 `AGENTS.md`，均无）。**在补登或裁定前，
   按 §7 与 ADR-0006 §2 字面判定为不一致。**
