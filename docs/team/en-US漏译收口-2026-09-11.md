## 2. 扫描口径（可复现）

遍历**整棵字典树**的全部叶子值，非只查字面量：

| 维度 | 口径 |
| :--- | :--- |
| 覆盖范围 | 对象递归（含任意深度嵌套）+ 数组元素（含数组套对象，如 `boot.steps[]`）+ **函数值以探针实参求值**（`("a","b","c")` 三个形参） |
| 取值方式 | 经 Vite SSR 加载真实 TS 模块（`ssrLoadModule("/src/content/en-US.ts")`），即运行时真值，非文本正则 |
| 命中判定 | `/[\u3000-\u303f\u4e00-\u9fff\uff00-\uffef]/`（汉字 + CJK 标点 + 全角字符） |
| 排除项 | 源码注释与 `/* */` 块（不进入字典树）；键名本身（只查值） |
| 实测规模 | en-US **641** 个叶子值 · zh-CN **641** 个叶子值（两侧键数对称，与 i18nStore 门禁一致） |

扫描命令（等价于门禁内核，用于一次性问清「还有多少处」）：

```bash
cd frontend && node --input-type=module -e '…ssrLoadModule + 递归取叶子…'
# 输出：en-US leaf values: 641 | CJK hits: 1
#   -> console.localeZh = "简体中文 (Chinese Simplified)"   ← 例外
```

## 3. 命中全清单与例外表

| # | 键路径 | 扫描时值 | 判定 | 处理 |
| :-- | :--- | :--- | :--- | :--- |
| 1 | `console.localeSystem` | `"System Default (跟随系统)"` | **真 i18n 缺陷**（en 用户可见中文） | 改 `"System Default"`（en-US:594） |
| 2 | `console.localeZh` | `"简体中文 (Chinese Simplified)"` | **有意例外：语言自名** | **不改**，白名单化（见下） |

**例外理由（`console.localeZh`）**：语言选择器按通行惯例（macOS / Firefox / VS Code）
以「该语言自身」书写选项名。en-US 用户在语言列表里看到「简体中文」是**正确行为**——
翻译成 "Chinese (Simplified)" 反而让该语言母语者难以辨认自己的语言。括注
`(Chinese Simplified)` 是给英文读者的补充说明，属同一惯例的一部分。
故**保留原值**，并在门禁 `INTENTIONAL_CJK` 例外表中显式登记（含本理由），
已有断言防止例外表腐化（键消失或不再含 CJK 即红）。

> 该例外**不是**"少改一处"：它被机器化登记，未来任何**新增**漏译都会因不在表内而红。

## 6. 新增门禁（`frontend/src/__tests__/enUsNoLeak.test.ts`，五例，纯逻辑无 DOM）

1. **扫描器自检**：叶子数 > 400 且抽样确认数组元素/嵌套对象/已知键均被遍历
   —— 防「walker 静默返回空数组」造成假绿；
2. **全量叶子值不含 CJK（例外表外）**：offenders 全量列出，一次问清；
3. **例外表防腐化**：表内键必须存在且确实含 CJK（已修好或键被删 ⇒ 红，逼例外表收敛）；
4. **例外必须带理由**：理由长度下限断言；
5. **语言/系统选项两侧纯净**：zh 的 `localeSystem`/`localeZh` 不得夹带英文括注，
   en 的 `localeSystem` 不得含 CJK 且须为 `System Default`。
