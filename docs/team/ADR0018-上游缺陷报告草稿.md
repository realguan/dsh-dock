# 上游缺陷报告草稿（dsh）：Windows 普通账户下 profile 模块 fallback 建符号链接失败

> 用途：ADR-0018 §5.1 要求的**必做项**。本文件是可直接粘贴到 dsh 仓库 issue 的正文草稿。
> 由 DSH Dock 壳侧维护者在 Windows 真机上发现，**非** dsh 源码改动请求（我们不改 dsh）。

---

## 标题

`Windows 非管理员/未开开发者模式账户无法启动 profile：profiles/node_modules 模块 fallback 使用 fs.symlinkSync（EPERM）`

## 环境

- dsh 版本：`@deepseek-ai/dsh@0.1.5-rc.2`（经查两源最新即此版：npmmirror / npmjs）
- Node：`v24.18.0`
- 平台：Windows x64
- 账户：**普通用户**（`IsAdministrator = False`），**开发者模式关闭**
  （`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\AppModelUnlock\AllowDevelopmentWithoutDevLicense = 0`）
- 启动方式：以 `node <dsh>/lib/bin.js --profile web --no-open` 启动（**非** pkg 打包可执行体）

## 现象

dsh 启动即退出（exit code 1）：

```text
EPERM: operation not permitted, symlink
  'C:\...\engines\dsh-runtime\node_modules\@deepseek-ai\dsh'
  -> 'C:\...\.dsh\profiles\node_modules\@deepseek-ai\dsh'
  errno: -4048, code: 'EPERM', syscall: 'symlink'
  at async runCli (.../@deepseek-ai/dsh/lib/bin.js:146:4)
  at async .../@deepseek-ai/dsh/lib/bin.js:168:23
```

## 根因（我们的定位，供参考）

`@deepseek-ai/dsh-app-boot` 的 profile 模块 fallback 逻辑：

- `isPackagedExecutable()` = `process.pkg !== undefined`；
- 非打包（普通 node）⇒ `ensureSymlink()` → `fs.symlinkSync`（`:612` 分支 `kind: "symlink"`）；
- 打包可执行体 ⇒ `ensureModuleProxy()` → **纯目录 + `entry-N.js` 再导出，零软链**。

Windows 上创建符号链接需要 `SeCreateSymbolicLinkPrivilege`（管理员）或用户开启开发者模式；
普通账户 `CreateSymbolicLink` 直接 `ERROR_ACCESS_DENIED`。**因此普通账户下 `.dsh/profiles/node_modules`
的第一个链接即失败，profile 无法启动。**

在 macOS 上以同一版本、同一方式启动，可复现同一行为但成功：dsh 会在
`$DSH_HOME/profiles/node_modules` 下建 **481 个符号链接**（Linux/macOS 建软链不需要特权，故不可见）。

## 影响面

**Windows 上未开开发者模式、非管理员的普通账户无法使用 dsh 的 profile 启动**
（宿主本地模式；WSL 客体因在 Linux 内不受影响）。

## 期望行为

Windows 上应能在**不需要任何特权**的情况下启动 profile。可选实现方向（供参考，非指定）：

1. 把 fallback 的链接方式按平台选择：Windows 上使用 **junction**（`fs.symlinkSync(target, path, "junction")`，
   无需特权）或直接使用既有的 **目录代理**分支；
2. 或把 `isPackagedExecutable()`（或其消费点）扩为「打包体 **或** 当前平台无法创建符号链接」；
3. 或在该平台跳过 fallback 并用其它等价解析机制。

## 我们的临时绕行（供上游知悉，非请求）

下游壳应用当前以自写 bootstrap 置 `process.pkg` 后 `import` dsh 入口并调用其导出的 `runCli()`，
使 dsh 走**它自带的**目录代理分支（实测软链 481 → 0，`profiles/node_modules` 下生成 1184 个
`entry-*.js` 代理，dsh 正常启动）。**这是对未公开内部判据的依赖，我们已登记为技术债**，
一旦上游提供正式支持（或发布独立平台打包体）即改用正式路径。

## 复现脚本（最小）

```powershell
# 前置：任意方式安装 @deepseek-ai/dsh 及其依赖（例如非全局 pnpm add 到一个临时目录）
$env:DSH_HOME = "$env:TEMP\dsh-repro\.dsh"     # 隔离 home，勿用真实 ~/.dsh
node <install>\node_modules\@deepseek-ai\dsh\lib\bin.js --profile web --no-open
# 期望：普通账户 + 开发者模式关闭时，报 EPERM: symlink（见上）
# 对照：同在 Windows 上以管理员或开启开发者模式运行，则成功
```
