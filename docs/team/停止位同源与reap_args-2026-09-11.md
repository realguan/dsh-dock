## 1. E3：复现红（只读阶段已实证，此处留档）

### 1.1 「本应拦住却放行」的实证

手法：把 `executor.rs` 的两个常量与 `guest_boot_script` 逐字搬进**独立探针**（不落仓库），
让常量取三个不同值，比较 `guest_boot_script("web")` 的**输出**。

```
常量 = /tmp/dsh-dock-stop        脚本 sha256 = 627465612c2d1ec09889d1179d5ff5d78221d1ddfb23e616ce5b082210e1d3c0
常量 = /tmp/dsh-dock-stop-x      脚本 sha256 = 627465612c2d1ec09889d1179d5ff5d78221d1ddfb23e616ce5b082210e1d3c0
常量 = /tmp/TOTALLY-DIFFERENT    脚本 sha256 = 627465612c2d1ec09889d1179d5ff5d78221d1ddfb23e616ce5b082210e1d3c0
```

**三次完全一致 ⇒ 改造前的脚本与常量零耦合**。于是：
- 宿主 `teardown` 的 `format!("touch {GUEST_STOP_FILE}")` 会 touch **新**路径；
- 客体脚本 `while [ ! -f 旧路径 ]` 永远等不到 ⇒ **停止位永不生效**；
- 而当时的测试断言 `plain.contains("/tmp/dsh-dock-stop")` 断言的正是**那个字面量** ⇒ **仍绿**。

> QA-verify 独立复现（lead 转达）：常量改 `-RENAMED` 后 executor 测试 **20/20 仍绿**。两路互证。

### 1.2 改造前后对照（同源化的直接证明）

| 时段 | 操作 | 脚本 sha256 | 结论 |
| :-- | :-- | :-- | :-- |
| 改造前 | 改常量值 | `6274656…`（**三次一致**） | 脚本**不跟随** ⇒ 静默失效 |
| 改造后 | 改常量值（`/tmp/PROOF-NEW-PATH`） | `64a50de62231c5369a2202f512b7e93d787a3d417804eff45c53663f172cdbea`（**与原值不同**），且新路径出现 **3** 次 | 脚本**跟随** ⇒ 同源生效 |

同一份源码、同一探针手法，**只差「脚本是否由常量构造」** —— 前后对照即同源性的正反证明。

## 2. E3：等价性证明（硬要求）

### 2.1 逐字节等价（`cmp`）

```bash
# 改前：从生产源码逐字提取 fixture 编译并运行
rustc --edition 2021 fixture.rs -o fixture && ./fixture > current_script.txt
# 改后：同样手法
rustc --edition 2021 after.rs  -o after  && ./after  > after_script.txt
cmp current_script.txt after_script.txt   # ← 无输出
```

| 项 | 改前 | 改后 |
| :-- | :-- | :-- |
| 字节数 | **589** | **589** |
| sha256 | `cb170d504066251e9febb5dfe5a5bb519ebefdaa7e8d8ccb4ccffb78222910fd` | **同左** |
| `cmp` | — | **无差异** |

⇒ **纯等价重构，零行为变更**（脚本是同一个字符串）。

### 2.2 转义/引号风险：评估结论 = 低，且已实证

| 风险源 | 实测结论 |
| :-- | :-- |
| 格式串内花括号 | 计数 **2 `{` / 2 `}`**，全部是既有占位符，**无裸花括号** ⇒ 不需要任何 `{{` / `}}` 转义 |
| shell 特殊字符 | `$HOME` / `$!` / `$?` / `$PID` / `2>&1` / `\"` 在 Rust `format!` 里**均非特殊字符** |
| 参数顺序歧义 | 改用**具名参数**（`stop=` / `ready=` / `prep=` / `prof=`），不再依赖位置顺序 |
| `sh_quote(profile)` 注入面 | 未改动，既有反例测试 `sh_quote_never_lets_metacharacters_escape` / `sh_quote_round_trips_through_bash` 全绿 |

### 2.3 一个必须做的 `cfg` 放宽（A 的必要组成）

| 项 | 改前 | 改后 |
| :-- | :-- | :-- |
| `GUEST_STOP_FILE` / `GUEST_READY_FILE` | `#[cfg(windows)]` | `#[cfg(any(windows, test))]` |

**为什么必须**：`guest_boot_script` 是 `#[cfg(any(windows, test))]` 且被测试调用。
直接把只在 `windows` 下存在的常量插进它 ⇒ **macOS/Linux 的 `cargo test` 编译失败**：

```
error[E0425]: cannot find value `GUEST_STOP_FILE` in this scope
  | #[cfg(windows)]  ------- the item is gated here
```

（2026-09-11 用 rustc 独立复现，非推演。）

**为什么安全**：非 windows 非 test 目标下 `guest_boot_script` **自身也被 cfg 掉**，
故常量不会成为"无人引用的 dead_code"；`cargo clippy` 宿主与 win-gnu **双目标均绿**（§6）佐证。

## 3. E3：门禁设计（两层，互补）

`guest_boot_script_inlines_guest_paths_from_constants`（`executor.rs`）分两层，
**两层都不够、必须都有**——这是本轮两次自测发现换来的：

| 层 | 断言 | 抓到什么 | 抓不到什么 |
| :-- | :-- | :-- | :-- |
| **1 计数** | `plain.matches(GUEST_STOP_FILE).count() == 3`（ready 同） | **漂移**：常量变了而脚本没跟上 ⇒ 计数下降 | 回退成**取值正确的**硬编码（两侧同变） |
| **2 源码参数化** | 生产段必须含 `"rm -f {stop} {ready};{prep}\` | **回退成硬编码**（来源不再单一） | —（第 1 层管漂移） |

### 3.1 自测发现 ①：「负向断言」是恒真式（已删）

首版我写了两条基于同一字面量的计数断言（`matches(GUEST_STOP_FILE)` 与
`matches("/tmp/dsh-dock-stop")`），并称之为"负向断言"。**自检证明二者恒等**：
常量当前取值就是那个字面量 ⇒ 两条断言永远同真同假 ⇒ **等于没测**。已删除，代之以第 2 层。

### 3.2 自测发现 ②：第 2 层自己也是恒真式（已修）

第 2 层首版写 `include_str!("executor.rs").contains("\"rm -f {stop} {ready};{prep}\\")`
—— **被搜索的串也出现在断言自身里** ⇒ 永远命中自己 ⇒ 恒真。
**变异实测暴露**：把生产段"彻底回退成硬编码 + 删具名参数"后，该断言**仍绿**（变异 3 首跑）。
修法：**只扫生产段**（`src[..find("\n#[cfg(test)]\nmod tests")]`），与 spawn 闸门排除测试段同源。
修后重跑同一变异 ⇒ **红**（§7 变异 3）。

> 这两次自测共同印证一条纪律：**文本判据的闸门必须同时排除「自身」与「测试段」**，
> 否则断言会退化为恒真式——而恒真式的外观与"绿灯"完全一样。

## 4. E2：`reap_args` 纯函数化（真单一来源）

### 4.1 问题

| 位置 | 改前 | 被测？ |
| :-- | :-- | :-- |
| `shell::windows_kill_args`（`:283`） | 自带 `vec!["/PID", pid, "/T", "/F"]` | ✅ `windows_kill_args_cover_whole_tree` |
| `lifecycle::reap_pid` 内联（`:887`） | 同形 `vec!` | ❌ **从未被断言** |

⇒ 同一语义**两处实现、只有一处被测**；清扫回退路径的参数构造一直裸奔。

### 4.2 修法（推荐 S，lead 已批准）

```rust
// lifecycle.rs —— 唯一实现（纯函数，跨平台可测）
#[cfg_attr(not(windows), allow(dead_code))]
pub(crate) fn reap_args(pid: u32) -> Vec<String> {
    vec!["/PID".to_string(), pid.to_string(), "/T".to_string(), "/F".to_string()]
}

// shell.rs —— 委托（本任务授权的唯一 shell.rs 改动，见下）
pub(crate) fn windows_kill_args(pid: u32) -> Vec<String> {
    crate::lifecycle::reap_args(pid)
}
```

**依赖方向**：`shell → lifecycle` **早已存在**（`shell.rs:101` `lifecycle::spawn`），
**未新增任何依赖边、不成环**。反向（`lifecycle → shell`）**禁止**，由 §4.4 闸门拦。

### 4.4 `lifecycle.rs` 依赖纪律闸门

`lifecycle_does_not_depend_on_state_holding_sibling_modules`：

## 5. 第三实例 `GUEST_PNPM_STAGING`：只读判定 = **响亮失败**（不纳入）

| 环节 | 代码 | 失配后行为 |
| :-- | :-- | :-- |
| 宿主投递 | `:1100` `wsl_unc_path(…, GUEST_PNPM_STAGING)` / `:1132` `base64 -d > {…}` | 写到**新**名 |
| 客体解包 | `:614` `tar -xzf /tmp/dsh-dock-pnpm.tgz`（**硬编码**旧名） | 文件不存在 ⇒ tar 非零 |
| 成败判定 | `:614-620`：`if tar … && mv … && chmod …; then … else echo STAGE_TAR_FAILED; …; fi; exit 0` | 落 `else` ⇒ 打印 `STAGE_TAR_FAILED` |
| 宿主消费 | `:759` `if !out.contains("STAGE_OK") { return Err(…) }` | **上抛 Err ⇒ 启动错误卡 + 诊断尾部** |

⇒ **用户可见、可诊断，不是静默**。且这是**设计如此**：`:606-607` 注释明写
「总有输出且 `exit 0`（成败看 `STAGE_OK` / `STAGE_TAR_FAILED` 行，规避
`run_with_timeout_raw` 的『非零退出=无输出』语义）」——**成败判定被刻意收归宿主**。

残余情形（均无害，如实登记）：① 旧名 tgz 不被 `rm -f` 清掉 ⇒ 遗留 `/tmp` 文件；
② 若只改脚本内 2 处字面量中的 `rm -f` 一处 ⇒ tar 仍成功、`STAGE_OK`、**正常但遗留一个包**。

⇒ 按 lead 判据（响亮 ⇒ 优先级低）**本轮不纳入**，登记为「同族但失败模式响亮」。
其同源化需把 `const = concat!(…)` 改 `fn` 并牵动 `:755` / `:1567`，属独立意图。
