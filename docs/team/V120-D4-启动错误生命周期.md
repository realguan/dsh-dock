## 2. 修复：把不变式做成结构，而不是调用点纪律

**改动面**：`src-tauri/src/boot.rs`、`src-tauri/src/commands/boot.rs`、`src-tauri/src/lib.rs`（构造点）。

原来三个并列字段（`boot_error` / `boot_steps` / `boot_generation`）收成一个
`BootRound`（`boot.rs`）：

```rust
pub(crate) struct BootRound {
    generation: AtomicU64,                        // 代际令牌
    error: Mutex<Option<serde_json::Value>>,      // 前端可见缓存：错误
    steps: Mutex<Vec<serde_json::Value>>,         // 前端可见缓存：步骤
}

impl BootRound {
    /// 开启一轮：先撤销上一轮的可见状态，再领取新代际令牌。
    pub(crate) fn begin_round(&self) -> u64 {
        self.clear_visible();                     // ← 不变式的唯一实现处
        self.generation.fetch_add(1, Ordering::SeqCst) + 1
    }
}
```

**为什么这样修**：此前「开启新一轮」与「撤销上一轮可见状态」是**两件分开的事**，
靠调用点自己记得配对——于是必然漂移（7 处起点只有 3 处配对）。
收成 `BootRound` 后两者是**同一个动作**，调用点**无从忘记**：这是把纪律变成结构。

**配套收敛（避免双写）**：删除 3 处已冗余的显式 `clear_boot_cache()` 调用
（`boot.rs:801` lib_boot_again、`:828` switch_mode、`commands/boot.rs:91` choose_mode），
并删除 `clear_boot_cache()` / `boot_error` / `boot_steps` / `boot_generation` 四个旧入口
（不再有「忘了调」或「调了两次」的余地）。

**语义保持（逐处核对）**：
- `boot.rs:766-768` 原为「先 `begin_boot()` 领令牌 → 再 `clear_boot_cache()`」；
  合并后为「先清 → 再领令牌」。**两者顺序无关正确性**（两把锁独立，领令牌不读缓存），
  且新的顺序更严格：即便失败发生在领令牌之后，也保证不会看到旧缓存。
- `commands/boot.rs:91` 原为「先清缓存 → 再解析 `data_dir` → 再领令牌」。
  合并时**刻意把轮次起点留在 `data_dir` 解析之后**：解析失败时本轮尚未开始，
  **不应作废在途启动**——与原行为的可观察语义一致。
- `boot_superseded()` / `boot_token_stale()` 判据未变（`boot_token_stale(current, token, shutting_down)`）。

## 4. 跨层契约（交 T-F 的 F3）

**后端已保证**：`begin_boot()` 返回后，`boot_error` 缓存必为空、`boot_steps` 必为空。
因此 `get_boot_status` 返回的**永远是当前轮次**的可见状态——新一轮已开始但尚无新错误时
`error` 必为 `null`，而不是上一轮的错误（该语义已写入 `commands/boot.rs` 的注释）。

**前端侧仍需做的（本轮由 T-F 实现，Lead 未碰 frontend/）**：
`bootStore.error` 无「新一轮开始」清零点。**注意不能只靠后端**：胶囊切换是 SPA 原地调用、
**不重载 document** ⇒ 不会重新走 `getBootStatus` 补水 ⇒ store 里的旧 error 原样留存。
建议在「模式握手发起 `chooseMode` 时」清一次 store（与 `bootStore.reset()` 的
「开始新一轮启动」语义合并，见 `bootStore.ts:146` 的既有注释），并补
**跨层接线断言**（「切模式后前端 error 必为空」）。
