## 4. 必验项 ③：错误保真（guard 不吞原始 Err）

- **Drop 实现**（best-effort，无 `unwrap`、不替换 Err）：

  ```rust
  impl Drop for TempScript {
      fn drop(&mut self) {
          if let Err(e) = fs::remove_file(&self.path) {
              tracing::debug!(path = %self.path.display(), error = %e,
                  "临时脚本清理未成功（忽略——不得覆盖原始错误）");
          }
      }
  }
  ```

  → 结构上**不可能**替换正在传播的 `Err`（`Drop` 本就无 `Result` 返回通道），且清理失败只留 debug 痕迹。✅

- **效力已证**：§2.2 第三轮变异（Drop 改 `unwrap()`）实测**红** → 说明「不得 panic」这条纪律真被拦住；错误保真断言在忠实复现下**红**（因为旧实现下 `?` 早退时错误本身仍在，红的点是清理断言）→ 断言确实在检查真东西。✅

## 8. 低危观察（不阻塞，建议下一轮登记）

### 观察：新测试自身的 scratch 清理**不是失败安全的**

5 个新用例的收尾是 `let _ = fs::remove_dir_all(&root);` **写在测试体末尾**——一旦测试**失败**（即恰好是检出回归的时刻），该语句不执行，`dsh-sess-leak-*` 目录**留在 `$TMPDIR`**。

**实测证据**：我本轮 4 次变异跑（均为「应有回归」的场景）共留下 **15 个** `dsh-sess-leak-*` 目录（`ls -ldt` 时间戳 14:24/14:26/14:27/14:29，PID `59489`/`60742`/`62656`/`64475` 与我各轮一致）。

**性质判定**：**低危**——只在 `$TMPDIR`、测试期产生、单轮 ≤5 个、无用户可见影响；且与 task-13 修的生产缺陷**不同源**（这是测试收敛问题，不是生产早退问题）。
**建议**：下一轮可把测试 scratch 也改成 RAII guard（或 `tempfile` 风格的 RAII，但 §5 禁引依赖 → 自建小 guard 即可）。**不建议本轮夹带**（AGENTS §8.2）。我已把本轮残留清干净，**当前归零态不受影响**。
