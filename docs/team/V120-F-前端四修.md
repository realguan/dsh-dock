## 2. F1：详情收不回

### 2.1 现状证据与判据

- `lib/bootTimeline.ts:41`（改前）：`if (v.hasError) return false` —— 一票否决。
- `pages/BootIndex.tsx`：`ErrorCard` 渲染在 `<section>` 内、向导块**之后**，与
  `isSetupMode ? <BootTimeline/> : <splash/>` 是**同级兄弟**——收起向导**不会**藏掉错误。
- ⇒ 否决只剩副作用：错误出现在「用户已点开详情」之后时，向导是用户自己开的却收不回（截图 ①/②）。

### 2.2 修法：三态意图（**不是**简单删掉 `hasError` 那行）

**实测证明「只删一行」会造出死按钮**（脚本枚举，见 §2.4）：收起只能把布尔置回 `false`，
而 `hasError`/`hasEverDownloaded` 仍为真 ⇒ `shouldShowTimeline` 恒真 ⇒ 按钮点了没反应。
且**改前就已有该潜在死按钮**：`hasEverDownloaded=true, hasError=false` 时按钮出现、点了无效。

故引入 `TimelineIntent = "auto" | "expanded" | "collapsed"`：
**显式意图压过自动信号**，收起才真正生效；`auto` 时仍由自动信号决定（日常秒启不展开）。

| 输入 | 改前 | 改后 |
| :--- | :--- | :--- |
| `collapsed`（用户点收起） | 不可能表达 | 恒隐藏向导 |
| `expanded` + `hasError` | 无收起出口（**缺陷**） | 展示 + 可收起 |
| `auto` + `hasError` | 展示 + 无收起出口 | 展示 + 可收起 |
| `auto` + 无任何信号 | 隐藏 | 隐藏（不变） |

### 2.3 测试

- **改写被锁定的旧用例**（任务要点 ②）：原 `it("出错时不给收起出口（错误必须可见）")`
  **逐字锁定了该缺陷**，已删除并在文件头与 `bootTimeline.ts` 注释写明**旧判据为何不成立**；
  **同时补了 5 条正向用例**（不只是删），故不构成「测试被削弱」。
- **真值表断言（非 vacuous）**：穷举 `4 种自动信号 × 3 种意图 = 12 格`的
  `(shouldShowTimeline, shouldOfferTimelineCollapse)` 显式期望值。
  > 说明：新判据下 `offer ⇒ show` 属**构造性成立**，若照旧写成
  > `if (offer(c)) expect(show(c)).toBe(true)` 就是断言恒真命题（装饰性断言）。
  > 故改为逐格写死期望值——任何一格算错都会红。该不变量仍保留，用于防未来打破。

### 2.4 复现先行的「死按钮」实测（设计决策证据）

```
场景：有错误 + 用户展开过，点「收起」→ forceShowTimeline=false
  点前 offer = true | isSetupMode = true
  点后 offer = false | isSetupMode = true   ← 按钮消失但向导仍在 = 死按钮
场景：下载过 + 无错误（现状即有的潜在死按钮）
  offer = true | isSetupMode = true   ← 按钮出现但点了无效
```

## 5. F4：更新进度表

### 5.1 现状证据与判据

`updater.rs` 真实序（**逐行核对**）：`:156` `Installing` → `:160-177` `Downloading`×N
（100ms 节流，**重复事件**）→ `:239` `Done` → `:246` `Relaunching`。

`TRANSITIONS`（改前）漏掉 **5 条真实迁移**（复现实测，非推断）：

```
被丢弃的迁移：[
  "available → installing",      // Rust 在下载前先发 Installing ⇒ 点下载无 loading
  "downloading → downloading",   // ×2 —— 重复进度 ⇒ 进度条冻结
  "downloading → done",          // 完成被丢
  "downloading → relaunching",   // 重启被丢
]
```

**进度冻结实测**：接受的进度采样 `[10]` vs 期望 `[10, 50, 90]`。

### 5.2 修法

补齐 5 条迁移 + `downloading → downloading` **自环**（显式注明"重复事件"）；并**订正那段
自相矛盾的注释**——原注释自称「锚定 updater.rs set_state 的全部调用位点」，实际并未锚定
（逐行核对后重写，含真实序图与三条缺口编号）。

**顺序无关设计**：`installing ⇄ downloading` 双向放行 —— 前端表**不绑定 Rust 内部时序**
（T-D6r 计划把 `Downloading` 提前），只拒绝真正无意义的跳转。
**守卫未被放宽**：`idle → done`、`idle → downloading`、`available → relaunching` 仍为非法（有断言）。

### 5.3 测试
