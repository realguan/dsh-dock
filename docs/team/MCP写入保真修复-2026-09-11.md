## 0. 一句话

`cordis.patch.yml` 的两套写入器（插件中心 / MCP 管理）**合并为唯一实现 `PatchFile`**：
未改动条目**逐字节原样回填**（行间注释、缩进、键序、引号风格全保）、覆写前**备份**、
**原子替换**。MCP 路径原先"注释全丢 + 无备份 + 键序被字典序打乱"三项一并消除。

## 1. 两写入器能力差异（**修复前**，如实核对）

| 能力 | 插件中心 `plugins.rs::write_patch_entries` | MCP 管理 `mcp.rs::save/delete_mcp_server` |
|:---|:---|:---|
| **原子写** | ❌ 裸 `std::fs::write` | ✅ tmp + rename |
| **覆写前备份** | ❌ 无 | ❌ 无 |
| **头部注释块**（文件首连续 `#`） | ✅ 保住（`read_patch_entries` 原文前置） | ❌ **丢** |
| **段间 / 行间注释** | ❌ 丢（正文整体重序列化） | ❌ **丢** |
| **键序** | ✅ 保住（`serde_yaml::Mapping` = IndexMap，解析后原序回写） | ❌ **被字典序打乱**（经 `serde_json::Value`：BTreeMap） |
| **缩进 / 引号风格** | ⚠️ 正文归一（2 空格；引号按需重选） | ⚠️ 全文件归一 |
| **顶层非数组拒绝** | ✅ 明确拒绝 | ❌ 无显式守卫（仅 YAML 解析错误） |

**结论：两者是半斤八两的互补缺失，不是"一个完备一个不完备"**——插件中心保注释但不原子不备份；
MCP 原子但注释与键序全丢。故任务方向（保真 + 备份 + 同源）正确，且**不能只把 MCP 改成调用旧插件写入器**
（那会拿"丢行间注释 + 非原子 + 无备份"换掉"丢全部注释"）。故改为**抽出统一实现**，两边同时受益。

## 3. 修复设计：唯一写入器 `PatchFile`

新增于 `plugins.rs`（`pub(crate)`，**两处路径共用**）：

```rust
pub(crate) struct PatchFile {
    header: String,              // 首部连续 `#`/空行块 → 永远原样前置
    preamble: String,            // 首个条目之前的内容（如 `---`）→ 原样保留
    raw: Vec<Option<String>>,    // 每条目的**原文片段**；None = 新构造/已改写
    pub(crate) entries: Vec<serde_yaml::Value>,
}
```

| 方法 | 作用 |
|:---|:---|
| `read(path)` / `empty()` | 读入（顶层非数组 → 拒绝）/ 目标文件不存在时的空载体 |
| `for_each_entry_mut(f)` | 逐条可变访问；闭包返回 `true` = 该条已改写 → 其 `raw` 置 `None` |
| `push(v)` / `retain(f)` | 追加 / 过滤（`raw` 与 `entries` **始终同长同序**） |
| `write(path)` | 拼装（未改条目**原样回填**）→ **先备份** → **原子替换** |

**关键技术点**：`raw` 的 `Some/None` **本身就是"是否已改写"的标记**——不需要调用方另传
"改动索引集"，因而不存在标记与实际不同步的可能；`retain` 同步增删两侧，杜绝索引错位。

**保真边界（如实声明）**：
- 未改动条目 → **逐字节**原样（含行间注释、缩进、键序、引号风格）；
- **被改写的那一条**（MCP 条目）→ 重新序列化，**其内部注释无法保留**。文件层无 CST
  解析器（`serde_yaml` 0.9 不保留注释），本仓库**不引新依赖**（AGENTS §5）——这是有意
  的已知代价，已写进代码注释。MCP 条目由壳机器生成（`id: mcp`），用户手写注释落在该
  条目内部的情形罕见，且**其余位置的注释现在全都保住**（此前是"整份文件全丢"）。
- 防御性回退：顶格 `- ` 行切分数 ≠ YAML 解析条目数（如**流式数组** `[{id: a}, {id: b}]`）
  → 放弃逐条保真、退回整文件重序列化（**值一个不少，绝不写坏**）。有专门用例覆盖。

**写入纪律**（与 settings / credentials 同口径）：
`fs_backup::backup_before_overwrite(path)?`（fail-closed：备份失败即中止写入）→ 同目录
隐藏临时文件 + `rename` 原子替换，失败时清临时文件并保住原文件。

## 4. 两处同源（钉死理由，已写入代码注释）

代码注释原文（`plugins.rs`，`PatchFile` 文档）：

> **两处必须同源（钉死理由）**：同一份用户数据 `profiles/<名>/cordis.patch.yml` 有两条写入
> 路径——插件中心（`set_plugin_disabled` / `copy_config_entries`）与 MCP 管理
> （`mcp.rs` 的 `save_mcp_server` / `delete_mcp_server`）。它们曾各写各的，于是**无声漂移成
> 两套行为**……两条路径都"能跑"，只在用户的注释被吃掉时才暴露——而 **YAML 注释是用户人工
> 资产，丢了不可逆**。故：本结构是唯一实现，任何触碰该文件的路径都必须调用它，**不得再写第二份**。

**同源后的调用点（4 处，全部走 `PatchFile`）**：

| 调用点 | 原实现 | 现状 |
|:---|:---|:---|
| `mcp.rs::save_mcp_server` | 自建 tmp+rename、丢注释 | ✅ `PatchFile` |
| `mcp.rs::delete_mcp_server` | 同上 | ✅ `PatchFile`（且**无改动不写盘**，不产生冗余备份/mtime 抖动） |
| `plugins.rs::set_plugin_disabled` | `read/write_patch_entries` | ✅ `PatchFile` |
| `plugins.rs::copy_config_entries` | 同上 | ✅ `PatchFile` |

旧的 `read_patch_entries` / `write_patch_entries` 已**整体删除**（grep 0 引用），
不留第二份实现。`:list_mcp_servers` 只读路径未动（无保真影响）。

**另注（非缺陷）**：`copy_config_entries` 的"原样复制"是把来源条目**作为值**追加进目标
（经 `push`），故复制过去的文本会按目标文件风格重新序列化——这与修复前 `seq.extend` +
整文件重序列化**语义等价**，无回归；ADR 口径的"原样复制"指**配置内容**而非字节。
