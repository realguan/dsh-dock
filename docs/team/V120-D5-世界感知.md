## 0. 结论一句话

关于页的版本/引擎维度改为**按当前运行世界择源**：`World::Local` → 宿主引擎
（行为零变化）；`World::Wsl{distro}` → **复用既有客体诊断通道**探测。
修前恒读宿主 `engines/`，WSL 模式下必然「未检出」（截图③）——与健康大盘
客体就绪（截图④）自相矛盾；修后两者同源。

## 3. 设计（复用了什么、为什么）

| 需求 | 落地 | 说明 |
|:---|:---|:---|
| 按世界择源 | `probe_source_for(&World) -> ProbeSource`（纯函数） | `Local → Host`；`Wsl{distro} → Guest{distro}` |
| **复用既有客体通道** | `probe_guest_versions` → `diagnostics::collect_diagnostics_in_guest` → `guest::diagnostics_script` | **零新脚本、零新 WSL 调用点**；`grep -c collect_diagnostics_in_guest` 仍为 1 处生产调用（既有）+ 我这一处消费，无第二实现 |
| 契约兼容 | 只改 `dsh.current` / `dsh.error` / `dsh.newer` / `node` 的**取值** | **不新增字段** ⇒ `ipc-shapes.json` 形状闸门与前端零改动（`cargo test` 全绿已证） |
| 探测失败 ≠ 未检出 | 失败 → `current=None` **且** `error=Some("<distro> 客体版本探测失败：<原因>")` | 与"客体确实没装"（`current=None, error=None`）**显式区分**，两条用例分别钉住 |
| 不阻塞启动 | `get_update_status` 由 sync 改 `async` + `spawn_blocking` | 客体探测起 `wsl.exe`（最坏 30s 超时）不冻结 IPC/主线程 |
| 缓存/惰性 | `cache_get_or_probe` + 60s TTL（按发行版分键） | **失败也缓存**（避免反复白付 30s 超时） |
| 版本归一 | `norm_guest_version` = trim + 剥一个 `v` | 与宿主 `engines::probe_engine` 的 `norm` 同口径；否则 `is_newer` 会拿 `v0` 比 `0` |
| 哨兵防护 | `guest_versions_from_report`（纯函数）按 `is_ready` 取值 | 未就绪时 version 是哨兵「未检出」，直接读会把哨兵当版本号显示 |

## 4. 性能与阻塞（量级证据）

| 证据 | 数据 |
|:---|:---|
| **缓存命中**（单测，注入计数探测） | TTL 内 **6 次调用 → 只探测 1 次**（命中 5 次）；到期后重新探测；换发行版重新探测；**失败 4 次调用 → 只探测 1 次** |
| 脚本自身开销（**宿主 bash 代理测量**） | 模拟客体 home（3 profiles × 200KB）：**首次 1.39s（冷启动），稳态 ~0.03s**（5 次实测） |
| 超时上限 | 客体通道固定 `30s`（`guest.rs:781`，既有实现，未改）⇒ 客体不可达时**最坏** 30s，且失败结论在 60s TTL 内复用 |
| **不阻塞启动（结构性）** | `get_update_status` 的 Rust 侧唯一消费者 = 关于页（`frontend/src/pages/About.tsx:41` ← `lib/resource.ts:13`）；启动链走**另一个**函数 `boot::refresh_update_ui`（`lib.rs:252` / `boot.rs:687` 独立线程），两者互不重叠 ⇒ 本改动**不进入启动路径** |
| 阻塞面收窄 | 命令改 `async` + `spawn_blocking`：探测不占用同步命令的 IPC 线程 |

> 边界（如实）：本机 macOS **无 WSL**，`guest::collect_diagnostics_in_guest` 在
> `#[cfg(not(windows))]` 下恒返回 Err（`guest.rs:796-801`），且 `mgmt::world_from`
> 在非 Windows 恒 `Local`（`mgmt.rs:51-61`）⇒ **客体分支在本机不可达**。
> 上表"脚本自身开销"是宿主 bash 的**代理测量**（证明脚本固有开销为毫秒级），
> **不是** WSL 实测；WSL 侧真实耗时须在 Windows 复验。

```bash
CC_x86_64_pc_windows_gnu=/tmp/fakebin/x86_64-w64-mingw32-gcc \
AR_x86_64_pc_windows_gnu=/tmp/fakebin/x86_64-w64-mingw32-ar \
```

## 6. 顺带发现（只记不修；跨域项交 Lead 派单）

### 6.1 spawn 闸门的 `cfg(test)` 截断只认 `mod tests`（**归 rust-core**）

- **实证**：我的测试模块名为 `mod world_probe_tests`，其中在宿主 bash 里真跑客体脚本的
  `std::process::Command::new("bash")…output()` 被闸门当成**生产代码**报红：
  `src/updates.rs:1563: .output()`。
- **机制**：闸门用**字面量标记**截断测试段——`lifecycle.rs:1818` 与 `:2436`
  的 `TEST_MOD_MARKER = "\n#[cfg(test)]\nmod tests"`；模块名不是 `mod tests` 时**截断失效**，
  测试段被当生产段扫。（对照：task-19 的网络面闸门用 `cfg_test_ranges` 做结构化范围判定，
  没有这个洞。）
- **我的处置**（在 write scope 内、走闸门自带的合规出口）：按闸门提示② 在本行加
  `// spawn-gate: exempt(测试专用…理由…2026-09-11)`。**未改 `lifecycle.rs`**（他域）。
- **建议**：rust-core 把该闸门的截断换成结构化 `cfg(test)` 范围判定（与网络面闸门同源），
  否则**任何非 `mod tests` 命名的测试模块里出现裸 spawn 都会误报**——这会让下一个人
  要么改模块名（游戏闸门）、要么加豁免（噪声）。

### 6.2 `check_updates` 仍会把关于页刷回宿主数据（**归 rust-core**，一处调用点）

- **链路**：关于页「检查更新」→ `commands/update.rs::check_updates` → `boot::refresh_update_ui`
  → `updates::check_now(data_dir)`（**无世界参数**）→ `emit_update` → 前端
  `lib/events.ts:43` `setVersions(...)` **覆盖**关于页刚播种的世界感知结果。
- **后果**：WSL 模式下点一次「检查更新」，关于页会**退回**「未检出」——与本次修复方向相反。
- **为什么我没修**：`refresh_update_ui` 在 `boot.rs`（**rust-core 写域**，简报明令不碰）；
  在 `commands/update.rs` 里另写一份 emitters/托盘刷新逻辑 = **第二实现**（简报第 3 条
  与仓库既有教训都禁止）。
- **建议（一行级）**：`boot.rs` 的 `refresh_update_ui` 把
  `crate::updates::check_now(&data_dir)` 换成
  `crate::updates::world_aware_status(crate::updates::check_now(&data_dir), &crate::mgmt::current_world(app)?)`
  （世界未定则 `status_world_unresolved`）。所需函数**已导出**，rust-core 可直接调用。

### 6.3 契约两处表达力不足（**归 frontend / 契约**，非本任务）

1. `ComponentUpdate.error` 的前端文案写死为「DSH 检测失败（**网络不可达**）」
   （`frontend/src/content/zh-CN.ts:222`）。客体探测失败也会落到这条文案 ⇒ 原因
   （WSL 不可达）被说成网络。**未新增字段**是硬约束（契约形状闸门），故本轮不解决；
   建议前端按 `error` 文本前缀分叉，或日后加独立的 cause 字段（属契约变更，需走流程）。
2. `NodeRuntimeInfo` **没有 error 槽**（`version: Option` 唯一表达），故客体探测失败时
   node 维度只能渲染「未安装」（`NodeVersionCard.tsx:40-43`），无法区分"客体没装"与
   "探测失败"——**node 维度的「探测失败 ≠ 未检出」在本契约下无法表达**，如实记录。

### 6.4 本次未覆盖的一处边界

`World::Wsl` 但发行版未记录（`mgmt::current_world` 返回 Err）时，我按 **ADR-0016
「绝不回落 Local」** 处理：不拿宿主数据冒充，而是把原因写进 `dsh.error`
（`status_world_unresolved`，有专门用例）。代价是该窗口内关于页显示「检测失败」而非版本。
判定为**可接受且更诚实**（该窗口 = WSL 模式尚未完成首次启动）。

## 7. 未决 / 风险（交 Lead 与 qa-verify）

1. **Windows 真机未验**（简报 §4 已裁定搁置）：客体分支的端到端行为（`wsl.exe` 实耗时、
   客体 PATH 下 `which dsh` 命中、`.dsh-dock/engines` 布局）**只能在 Windows 复验**。
   本机证据止于：纯逻辑分支、报告映射、**真脚本在宿主 bash 的执行与解析**。
   故本任务结论口径 = **机制级修复 + 单元/契约级验证，真机待复验**，不得写成"已修好"。
2. §6.2 未修 ⇒ **WSL 模式下「检查更新」按钮仍会刷回宿主结论**；在此项修掉前，
   关于页首帧正确、手动刷新后可能回退。
3. 客体 30s 超时对 UX 偏长（首次加载最坏 30s）；缓存后不再重复，但**断网/WSL 挂死**时
   首帧会等满。若维护者认为需收窄，属 `guest.rs` 的超时口径调整（本任务未动）。
4. 未做真实 WSL 上的 `du` 规模压力测试（客体 home 很大时脚本耗时未量）。
