## 3. S1 修复（本次合并的核心，不是机械解冲突）

### 3.1 缺口（合并前诊断）

分支的客体 patch 写入走 `parse_patch_entries` / `render_patch_entries`：

- `render_patch_entries` = 头部注释块 + `serde_yaml::to_string(seq)` **整数组重序列化**
  ⇒ **除头部连续注释块外全部注释丢失**（分支自述「已知代价」）；
- 客体写入 `guest::write_home_files` 只有 `base64 -d > tmp` + `mv -f`（原子但**无备份**）；
- 而 AGENTS §6 已登记「**统一走 `plugins.rs::PatchFile`**」⇒ 直接合并会让登记失真。

### 3.2 修复机制（让宿主与客体**共用同一份保真语义**）

- `PatchFile::from_text` 提为 `pub(crate)`；抽出**纯函数** `render()`；
  `write()` 语义不变 = `render()` + `backup_before_overwrite`（**fail-closed**）+ 原子替换；
- **删除分支第二套内核**（`parse_patch_entries` / `render_patch_entries` /
  `read_patch_entries` / `write_patch_entries`）——§6「不得再写第二份」；
- **四条客体 patch 写入路径**全部改为「同一内核 + 客体侧备份 + 原子写」：

| 路径 | 原状态 | 现状 |
| :--- | :--- | :--- |
| `plugins::set_plugin_disabled_in_guest` | 旧内核、无备份 | `PatchFile::from_text`→`render` + `backup_file` |
| `plugins::copy_plugin_config`（客体分支） | 旧内核、**无备份** | 同上（**本次审计新发现，第 4 条**） |
| `mcp::save_mcp_server_in_guest` | 经 `serde_json` 中转、无备份 | 同源内核 + `backup_file` |
| `mcp::delete_mcp_server_in_guest` | 同上 | 同源内核 + `backup_file` |

- `mcp.rs` 的 upsert/remove 提取为**共用内核**，宿主与客体文本变换同源；
  未命中即**逐字节原样返回**（不重序列化 ⇒ 无无谓 diff / 无无谓备份）。
