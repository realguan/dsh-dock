```bat

"%~dp0node.exe" "%~dp0..\dsh-runtime\node_modules\@deepseek-ai\dsh\lib\bin.js" %*
```

⇒ 目标路径 = `dsh-runtime/node_modules/@deepseek-ai/dsh/lib/bin.js` ✅；`%~dp0` **相对**（引擎目录搬迁仍可用）✅；CRLF ✅；**纯 ASCII** ✅（控制台代码页）。

### 6.2 **一个重要旁证（M2 的副产品）**：只有一条测试真正钉住「入口路径」

M2 变异（`dsh_entry_js` 的 `bin.js`→`index.js`）结果：

```text
test engines::tests::posix_shim_shape_is_exact ...................... ok   ← 未红
test engines::tests::windows_shim_shape_is_exact .................... ok   ← 未红
test engines::tests::both_platform_shims_target_the_same_relative_entry ok ← 未红

```

**为什么这是合理的（我读了三条 shape 测试确认）**：这三条对 **纯函数/常量**分别喂**独立字面量**输入（`posix_shim_shape_is_exact` 把字面量 `entry` 传进 `dsh_shim_posix`；`windows_shim_shape_is_exact` 断言 Windows 常量里的完整字面量路径）⇒ 它们验的是**格式化**，**不覆盖 `dsh_entry_js` → shim 的接线**。**唯一覆盖该接线的是 `generated_shim_executes_and_forwards_args`**，而它刻意用**独立字面量** `EXPECT_TAIL`（注释还明确引用了「qa-verify 两态等价教训」）。
⇒ **结论：该接线的防回归**完全压在这一条测试上**；它有效（M2 红），但**单点**。若将来删改它，路径回归将静默。**建议（非阻塞）**：把 `EXPECT_TAIL` 那条独立字面量断言同时加到 `both_platform_shims_target_the_same_relative_entry` 的 POSIX 分支（该测试已有「独立字面量」的自觉，作者在注释里记过一次「裸段检查确实没红」的教训）。
另外 `dsh_install_uses_project_local_path` 是**生产段 presence 断言**（`contains("pnpm_project_install_args")` / `contains("dsh-runtime")`）——只钉「存在」，不钉行为；作为源码闸门的补充可接受，不应单独当作行为保证。

### 6.3 `find_engine_tool` 查找序断言是否只是实现细节？
