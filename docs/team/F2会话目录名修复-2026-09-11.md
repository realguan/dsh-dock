## 2. 方案选择：**取 ②（字节判据）**，理由三条

```diff
-    let is_windows = stripped.len() >= 2 && stripped.chars().nth(1) == Some(':');
+    let is_windows = stripped.as_bytes().get(1) == Some(&b':');
```

1. **不变式可证**：`':'` = `0x3A` 在 UTF-8 中不可能是多字节序列的续字节
   （续字节 ∈ `0x80..=0xBF`，前导字节 ≥ `0xC2`）。故 `as_bytes()[1] == b':'`
   **蕴含**字节 0 是完整单字节字符、字节 2 必为字符边界 —— 下方
   `&stripped[..2]` / `stripped[2..]` 因此**恒定安全**，不是「碰巧不炸」。
2. **治根而非绕行**：缺陷本体是「判据量纲 ≠ 切片量纲」。② 让两者同为字节量纲；
   ① `char_indices().nth(2)` 则要额外处理「不足 3 字符」的 `None`，且把**字符**
   切点喂给**字节**切片——仍让两个量纲共存，后人照抄易再错。
3. **语义更正确**：Windows 盘符定义即「单个 ASCII 字符 + `:`」。② 下 `"信:"`
   被判为非盘符、走 POSIX 相对路径（实测 `/信:`）；① 会把它当盘符产出
   `"信:\"` 这种无意义基路径。**旧实现是 panic，无既有行为需要保留**。

`.get(1)` 天然覆盖「长度 < 2」（`None`），故删去冗余的 `len() >= 2`。
量纲裁定已按 2026-09-11 体例写入代码注释（见 diff）。

## 4. 调用方同量纲隐患复核（task-12 第 4 项，**只读未改**）

**结论：`decode_project_dir_name` / `decode_project_dir_to_path` 的调用方无其它同量纲隐患。**

- 生产调用方**仅 2 处，都在 `scan_sessions` 内**：`sessions.rs:210`（`decode_project_dir_name`）、
  `sessions.rs:272`（`decode_project_dir_to_path`）；其余命中全在 `#[cfg(test)]` 内。

  **Rust 侧下游无二次切片**（全仓 grep 确认）。
- 前端消费为 `projectName.toLowerCase().includes(q)`（`SessionManager.tsx:250-251`）与
  CSS `truncate`——JS 字符串是 UTF-16、`includes`/`truncate` 无字节假设，安全。
- 函数体内其余索引运算已逐条核对安全：`segments[i..i + len]`（`len ≤ segments.len() - i`，
  由 `max_lookahead` 保证）、`segments[i]`、`raw.trim_matches('-')`（字符边界安全）。
