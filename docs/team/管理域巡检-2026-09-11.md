## 2. fix 候选（按建议优先级）

### F1 —— `mask_api_key` 对非 ASCII 凭据值 panic；release 下 `panic="abort"` = 应用被杀 · **高**

- **证据**：`src-tauri/src/credentials.rs:45-46` 用**字节下标**切片
  （`&trimmed[..4]` / `&trimmed[trimmed.len()-4..]`），未做 char boundary 校验；
  `Cargo.toml:52` `[profile.release] panic = "abort"`。
- **可达路径**：`.credentials.yaml` 中任一**字符串值**含多字节字符（如手写中文备注、全角字符）→
  `get_credentials_summary`（`credentials.rs:170`，前端凭据面板加载即调：`CredentialsPane.tsx:50`）
  → `mask_api_key` → `end byte index 4 is not a char boundary` panic。
  隔离复算（同一函数体，`rustc -O`）：`"凭据测试值abcd"`、`"密钥测试值"` 均 panic。
- **影响**：debug 下该 IPC 返回错误（凭据面板整页失败）；**release 下 `panic="abort"` 直接终止壳进程**。
- **建议修法**：按 `char_indices()` 取前/后 4 个**字符**（或 `chars().take(4)` + `rev().take(4)`），
  非 ASCII 与短串一并收口；`mask_api_key` 是纯函数，**补 3 条内联用例**（中文值 / 混合值 / 9 字节边界）即满足 AGENTS §5。
- **顺带**：F6 同一函数。

### F2 —— 删除会话前不消费「可能正在写入」判据 · **中**

- **证据**：`src-tauri/src/sessions.rs:538-566`（`remove_session` 直接 `remove_dir_all` 会话目录，
  连 `session.lock` 一并 unlink）；`src-tauri/src/commands/session.rs:73-80`（命令层无判据）；
  前端确认框文案泛化：`frontend/src/components/profiles/SessionManager.tsx:776-790` +
  `zh-CN.ts` 的 `sessions.deleteConfirmTitle` / `deleteConfirmNote`（只写「永久删除…不可撤销」）。
  > 注：本轮读取时该二键在 `zh-CN.ts:540-541`；巡检期间有并发前端编辑，**以键名定位为准**，
  > Rust 侧行号不受影响。
- **已具备但未接入的判据**：`list_sessions` 已返回 `SessionItem.active`（`sessions.rs:46`，
  复合判据实现于 `scripts/repair-session.mjs:1511`：引擎存活 ∧ mtime<5min ∧ `endState==='open'`），
  删除路径与确认框都没用它。
- **建议修法**：**只动前端**（确认框在 `active` 时追加一行「该会话可能正被 dsh 写入」文案 + 1 个 i18n 键），
  不碰锁——`src-tauri/src/lifecycle.rs:22-24` 明写「绝不触碰 dsh 的会话写租约」是 ADR-0015 边界纪律，
  壳侧只做提示不代管。

### F3 —— MCP 写 `cordis.patch.yml` 丢注释、无备份，且与同文件另一写入器不一致 · **中**

- **证据**：`src-tauri/src/mcp.rs:47` / `:128` 以 `Vec<serde_json::Value>` 解析，
  `:192` / `:234` 整数组重新序列化 → **文件头注释块被抹掉**，无 `fs_backup` 调用（全文件无 backup）。
  对照同文件的另一写入器 `src-tauri/src/plugins.rs:934-969`（`read_patch_entries`/`write_patch_entries`
  显式保留头部注释块，`:971-972` 注释写明「注释为用户可见文档，序列化会丢其余位置注释，已知代价」）——
  同域两条写入路径**保真等级不一致**。
- **登记状态**：AGENTS §6 写入例外册只登记了 #2（web-app 声明单键追加）、#4（copy_plugin_config
  配置行原样复制）、#5（pnpm-workspace 单键）；`:971` 自称「写入例外 #3」（set_plugin_disabled）
  亦未进 AGENTS 正文。**MCP 的整文件读改写无任何例外册条目**（§5.2 偏差 3）。
- **建议修法**：MCP 读写改走 `plugins.rs` 已有头部保真助手（含 `[]` 空文档兜底），
  覆写前接 `fs_backup::backup_before_overwrite`；补「首部注释保留」回归用例。
- **附**：`delete_mcp_server` 会留下空 `config.mcpServers` 条目（对照 `set_plugin_disabled` 的整条清理语义，`:1012-1019`）。

### F4 —— `set_shell_settings` 仍是整体覆盖写（09-08 明确遗留） · **中**

- **证据**：`src-tauri/src/commands/console.rs:17-26` 直接把前端传的整个 `ShellSettings` 落盘；
  `src-tauri/src/settings.rs:74-81` `save` 序列化**全字段**，无 merge 语义。
  09-08 登记原文：`docs/known-issues/问题记录-2026-09-08.md:133-135`——「前端已加安全基线，
  但**任何新调用点仍可能踩坑**；建议在 `settings.rs` 侧补 merge 或收窄命令面（收窄属契约改动 → 先 ADR）」。
- **现状核对**：仓库内现有调用点均为 load-modify-save（`boot.rs:769-771`、
  `commands/boot.rs:98-100`、`commands/profile.rs:95/134/158`），**暂无活跃缺陷**；
  风险面 = 未来新调用点 + 前端旧版载荷。
- **建议修法**：见 A1（merge 语义 vs 收窄命令面，需先裁定）。

### F5 —— `set_provider_key` 无备份、且整文件重排（丢注释） · **低**

- **证据**：`src-tauri/src/credentials.rs:303-347`：解析为 `BTreeMap<String, Value>`（键序变字典序）
  → 改键 → `write_credentials` 全量写回；对比原文覆写路径 `:297-300` 显式先备份。
  用户手写在 `.credentials.yaml` 的注释在同一文件的两条写入路径下**一条保、一条丢**。
- **建议修法**：`set_provider_key` 也接 `backup_before_overwrite`；注释保真若要一并解决需
  文本级改写（成本高，可另立）；至少补「既有他键不丢」的现有测试断言（已知
  `credentials.rs:377` 有用例，核对是否覆盖注释场景）。

### F6 —— `mask_api_key` 短 key 过度披露 · **低**

- **证据**：`credentials.rs:42-47`：`len<=8` 全掩码，但 `len==9` 时前缀 4 + 后缀 4 =
  **9 个字符里 8 个明文可见**（实测 `abcdefghi` → `abcd••••••••fghi`）。
- **建议修法**：与 F1 同一函数，顺带把「可见字符数 ≤ 4」写成断言式用例。
