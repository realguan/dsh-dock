### 2.3 条目间注释的归属细节（我额外发现，非缺陷但值得登记）

我构造了**不缩进的条目间注释**：

```console
raw[0] = Some("- id: first\n  name: one\n# 这条注释在 first 与 second 之间\n")
raw[1] = Some("- id: second\n  name: two\n")

改 first 后：条目间注释是否仍在 = false   ← 注释随 first 一起被重序列化而丢失
```

**判定**：条目间注释在实现上归属**上一条**的 raw 切片。⇒ 若视觉上它「属于下一条」，改写上一条会连它一起丢失。**与 §2.1 的已知代价同源**（都是「被改写那一条的 raw 失效」），**不是新缺陷**，但**值得写进已知代价清单**（用户可能把注释写在两条之间且以为它跟着下一条）。

## 6. lead 追加项 E3：`GUEST_STOP_FILE` 常量↔字面量耦合 —— **复核结论：lead 判断完全成立，且我实测坐实**

### 6.1 事实核对（`实测`）

```console
$ grep -n "GUEST_STOP_FILE\|dsh-dock-stop" src-tauri/src/executor.rs
524:const GUEST_STOP_FILE: &str = "/tmp/dsh-dock-stop";
579:        "rm -f /tmp/dsh-dock-stop /tmp/dsh-dock-ready;{}\
581:         (while [ ! -f /tmp/dsh-dock-stop ]; do sleep 1; done; kill -TERM \"$PID\" …) & WATCH=$!;\

970:        //    内其它进程。注意 /tmp/dsh-dock-stop 须与 guest_boot_script 内字面量一致。
972:            let script = format!("touch {GUEST_STOP_FILE}");
1303:        assert!(plain.contains("/tmp/dsh-dock-stop"));
```

⇒ 宿主 `:972` 用**常量**；客体脚本 `:579/581/582` 写死**字面量**；测试 `:1303` 断言的**也是字面量**；`:970` 用**注释**承认耦合。**用注释防，没有机器防** —— 与 lead 描述一致 ✅

### 6.2 「改常量而不改字面量 ⇒ 停止位静默失效 + 测试仍绿」**实验坐实**

```console
$ # 变异：只改常量 → "/tmp/dsh-dock-stop-RENAMED"（不动脚本字面量、不动测试断言）
--- 宿主 touch 的路径现在是： let script = format!("touch {GUEST_STOP_FILE}");
--- 客体脚本仍在轮询：     while [ ! -f /tmp/dsh-dock-stop ]
--- 跑全套 executor 测试 ---
test result: ok. 20 passed; 0 failed; 0 ignored; 0 measured; 307 filtered out
### RESTORED = abc2265896eaf275 expect=abc2265896eaf275 ✅
```

⇒ **宿主 touch 新路径、客体轮询旧路径 ⇒ 停止位永不生效（stop 静默失效），而 20 个 executor 测试全绿**。lead 的「测试因断言同一字面量仍绿」判断**属实**。

**我的补充定性**：
- 这是**静默失效**（无报错、无日志、UI 无提示）——比崩溃更难排查，属**高价值发现**。
- **触发条件**：只有「有人同时改常量却不改三处字面量」时才发作 ⇒ 属**潜在缺陷 / 防复发缺口**，非当前活动 bug。
- **建议防复发（交修复者参考）**：让 `guest_boot_script` **由常量拼接**（`format!` 注入）而非字面量，并把 `:1303` 的断言改为**跨两侧一致性**断言（断言「脚本包含 `format!("touch {GUEST_STOP_FILE}")` 的同一路径」），即**用机器防取代注释防**。
- 已计入 §8「未设防」清单。
