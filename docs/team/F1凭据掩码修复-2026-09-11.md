## 2. 最小修复（`src-tauri/src/credentials.rs::mask_api_key`）

```diff
-    if trimmed.len() <= 8 {
+    let chars: Vec<char> = trimmed.chars().collect();
+    if chars.len() <= 8 {
         return "••••••••".to_string();
     }
-    let prefix = &trimmed[..4];
-    let suffix = &trimmed[trimmed.len() - 4..];
+    let prefix: String = chars[..4].iter().collect();
+    let suffix: String = chars[chars.len() - 4..].iter().collect();
```

**掩码语义裁定（本任务明确决定）**：按**字符数**——前 4 字符 + `••••••••` + 后 4 字符；
字符数 ≤ 8 时整串掩掉（维持既有 `"••••••••"` 回退语义，未改）。

两处根因同修：① 切片边界（panic 源）；② **长度判据**——旧 `len() <= 8` 是字节判据，
「3 个 CJK 字符 = 9 字节」会误入切片分支，只修切片不修判据则语义仍错（3 字符的短值
被当成超长值披露前后缀）。

## 5. 同类字节切片隐患（**只记不修**，交 lead 排期）

### 5.1 真隐患 1 处：`src-tauri/src/sessions.rs:96-97`

```rust
let is_windows = stripped.len() >= 2 && stripped.chars().nth(1) == Some(':');
let (sep, mut current_base, remaining_raw) = if is_windows {
    let drive = &stripped[..2];                 // :96 ← 字节切片
    let rest = stripped[2..].trim_start_matches('-');   // :97 ← 字节切片
```

- **判据与切片的量纲不一致**（与 F1 同款）：`chars().nth(1) == Some(':')` 只保证
  **第 2 个字符**是冒号，不保证**字节 2** 是边界。若首字符是多字节、第 2 字符是 `:`，
  则字节 2 落在首字符内部 → panic。
- **实机复算**（复刻 :94-96 判据与切片，`rustc -O`，未改仓库代码）：

  ```
  "C:-Users-guan-" -> ok C:\
  "信:"            -> PANIC
  "密钥:"          -> ok /
  "A:"             -> ok A:\

  thread 'main' panicked: end byte index 2 is not a char boundary; it is inside '信' (bytes 0..3 of string)
  ```

  （`"密钥:"` 不中招是因为 `nth(1)` 是「钥」而非 `:`——触发条件是**单**多字节字符紧跟冒号。）
- **可达路径**：`scan_sessions`（`sessions.rs:196`）对 `$DSH_HOME/sessions/` 下每个
  **目录名**调 `decode_project_dir_name` → `decode_project_dir_to_path`。目录名由 dsh 生成
  时恒为 ASCII 编码路径，故**日常不触发**；但该目录可由用户手工创建/改名，**一旦出现即
  在会话面板加载时 panic**——release `panic = "abort"` 下同样是**杀进程**，放大效应与 F1 同源。
- **建议修复方向**（未实施）：改用 `char_indices().nth(2)` 取第 3 个字符的字节起点作为切点；
  或依赖 UTF-8 性质断言 `stripped.as_bytes().get(1) == Some(&b':')`（ASCII `0x3A` 不可能出现在
  多字节序列的续字节位置，此时字节 2 必为边界）后再切片。**同批建议补一条 `"信:"` 反例用例。**
