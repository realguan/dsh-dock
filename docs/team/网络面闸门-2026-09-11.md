## 2. 判据口径（每条设计决定都有反例背景）

### 2.1 判据是「是否发起请求」，不是「是否出现 URL」

任务明确要求这条。实测 URL 字面量分布：`build_policy.rs` / `commands/link.rs` / `engines.rs` /
`executor.rs` / `lib.rs` / `plugins.rs` / `profiles.rs` / `resolve.rs` / `shell.rs` / `ui.rs` /
`updater.rs` / `updates.rs` ——**12 个文件**（实测 `grep -rln "http://\|https://" src`）。
若按 URL 判，豁免表要收 12 个文件里的几十处常量，闸门当场腐化成"人人加豁免"。

故只认**网络原语标识符**（`PRIMITIVES`，10 条）：`ureq` / `reqwest` / `hyper::` / `tonic::` /
`UpdaterExt` / `TcpStream` / `TcpListener` / `UdpSocket` / `"curl"` / `"wget"`。
刻意**不**收录 `SocketAddr` / `IpAddr`（纯类型，不发请求）与 `.connect(`（Tauri / DB / 通道都会用）。

### 2.2 只扫生产代码——用**求值**，不是"含 test 就算"

`#[cfg(not(test))]`（`resolve.rs:91` 实际用法）与 `#[cfg(all(not(test), unix))]` 都是**生产代码**；
反过来 `#[cfg(any(test, unix))]` 含 `test` 但在 unix 生产构建里同样编译。故实现为：

```rust
fn cfg_eval(pred, test: bool) -> bool          // test / not / any / all 递归求值
fn cfg_pred_is_test(pred) -> bool { !cfg_eval(pred,false) && cfg_eval(pred,true) }
```

**这条差点写错**：首版把 `all(...)` 实现成"所有子谓词都是 test"，于是 `all(test, unix)`
被判成**非**测试专用（`unix` 子谓词返回 false）→ `resolve.rs:105` 的测试专用条目会被当生产代码扫。
是 `cfg_predicate_evaluation_is_not_substring_matching` 用例先红才暴露的（见 §5 的"测试先行"注）。

### 2.3 两个文本视图（避免"用户文案里的 ureq 被误报"）

| 视图 | 抹掉什么 | 判什么 |
| :-- | :-- | :-- |
| `code` | 注释 **+ 字符串字面量** | 标识符原语（`ureq` / `TcpStream` / …） |
| `argv0` | 只抹注释（保留字面量） | `"curl"` / `"wget"`（它们必须带引号才有意义） |

缺任一个都会出错：只有一个"保留字面量"的视图 → 一句文案里出现 `ureq::` 就误报
（首版如此，`comments_are_not_scanned` 抓出）；只有一个"抹字面量"的视图 → `Command::new("curl")` 漏检。

### 2.4 CRLF：加了，但**它不是唯一防线**（诚实留痕）

扫描前 `\r\n` → `\n`，并配 `crlf_sources_are_judged_identically`（断言 LF 与 CRLF 报出**相同行号**）。
**变异测试 C 的结论**：把这行归一删掉，该用例**仍然绿**——因为本闸门是**行式**设计
（`.lines()` 切分、谓词先 `trim()`、`\r` 被 `is_ascii_whitespace()` 吃掉、配对只看 ASCII 结构字符），
天然抗 CRLF。归一是**纵深防御**（防未来有人把扫描改成整段子串匹配 / 锚定 `$`），不是本设计的命门。
——不把"加了归一"写成"归一救了闸门"，是因为本轮真跑了变异测试，结论就是上面这句。

### 2.5 运行时遍历，不用 `include_str!` 白名单（**关键设计决定**）

spawn 闸门用 `include_str!` 显式清单——那对"进程 spawn"够用（seam 就在少数几个文件里），
但**本闸门要防的正是"没人记得登记"**。若扫描面也要人记得加文件名，等于把同一个漏洞换个地方再犯：
新增文件里的网络调用会被**静默漏扫**（这正是 `boot.rs` 那次漏登记的同构形态）。

故 `source_files()` 运行时遍历 `env!("CARGO_MANIFEST_DIR")/src/**/*.rs`（**实测 35 个文件**，
含 `src/commands/**` 子目录）。代价与兜底：路径错会让闸门"零文件全绿"，故主闸门先断言
`files.len() >= 25` 且必须含 `lib.rs` / `updates.rs` / `boot.rs` / `plugins.rs`，
并断言豁免表里每个路径都真实存在。

## 3. 豁免表（唯一事实源 = AGENTS §7）

### 3.1 表内容

| 文件 | 条目 | 种类 | 理由 | 日期 |
| :-- | :-- | :-- | :-- | :-- |

| `src/updater.rs` | 整文件 | **Exempt** | 客户端自更新（AGENTS §7 补登记）：驱动 tauri-plugin-updater 的 check / download / install | 2026-09-11 |
| `src/boot.rs` | **仅 `authenticate_workbench_session`** | **Exempt** | 工作台 Token 环回兑换（AGENTS §7 2026-09-11 补登记）：127.0.0.1 GET、5s、redirects=0 | 2026-09-11 |
| `src/plugins.rs` | 整文件 | **Exempt** | 插件运行态环回只读查询（AGENTS §7 2026-08-29）：POST 127.0.0.1 /api/pluginInventory/list，2s | 2026-09-11 |
| `src/engines.rs` | 整文件 | **Registered**（不授权） | 引擎引导（AGENTS §7）：网络在 `pnpm` **子进程**内，本文件零 in-process 原语 | 2026-09-11 |
| `src/executor.rs` | 整文件 | **Registered**（不授权） | WSL 客体投递（AGENTS §7）：网络在**客体进程**内，本文件零 in-process 原语 | 2026-09-11 |

### 3.2 「Registered 不授权」是本任务唯一一处对指令的**刻意收紧**，请你裁定

你给的六个登记面**都在表里**（理由 + 日期齐全，与 AGENTS §7 逐条对齐）。区别在**种类**：

- `plugins.rs` / `updates.rs` / `updater.rs` / `boot.rs` 今天**真的命中**原语 → `Exempt`（授予豁免）；
- `engines.rs` / `executor.rs` 今天**零命中**（实测：它们的网络是 `pnpm` / `wsl.exe`
  **子进程**发起的，本文件没有任何 in-process 原语，只有 `https://…` 常量）。

给一个今天零原语的文件开**整文件豁口**，等于预授权它未来任意触网。故它们记为
`Registered`（在册、不授权），并由 `registered_entries_have_no_in_process_primitives`
钉住"今天确实零命中"——一旦有人在引擎引导里直接 `ureq::get`，测试会红并逼出显式决定：
把网络收回 `updates.rs`，或把它改成 `Exempt` 并同步 AGENTS §7。

> 若你要求严格"六个都豁免"，把 `kind` 改成 `Exempt` 即可（一行），但那样会失去上面这条保护。
> **建议保留现设计**；本项列为本轮唯一待你确认的口径。

### 3.3 为什么不用内联标注（与 spawn 闸门的取舍相反）

spawn 闸门用 `// spawn-gate: exempt(...)` 行内/邻行标注——理由成立（spawn 面就在本域内）。
本闸门**刻意改为集中表**：

1. **跨域**：`plugins.rs` 属 `rust-mgmt`，`boot.rs` 属本域，`updater.rs`/`updates.rs` 属本域
   ——若用内联标注，"过一次闸门"的改动就要散落到非本域文件，与独占写入范围直接冲突
   （`docs/team/README.md` §1）；
2. **集中表可被机器自检**：`exemptions_are_live` 能证明"每条都在挡东西"，
   内联标注做不到（标注是注释，扫描器不知道它是否还有效）；
3. **内联标注与"不漏登记"目标相斥**：标注写在被豁免处，等于把审计点放到最不容易被审的地方。

### 3.4 豁免表的自检（三条测试）

| 测试 | 钉住什么 | 实测效果 |
| :-- | :-- | :-- |
| `exemptions_are_live` | 每条 `Exempt` 摘掉后**必须真的报违规**（防"空条目/过宽条目"） | **当场删掉了第 7 条**：首版给自己（`network_gate.rs`）加了豁免，但本文件的原语示例全在 `#[cfg(test)] mod tests` 里、模式串是字符串字面量（代码视图会抹掉）→ 该条目是**空条目**，测试判红后删除 |
| `registered_entries_have_no_in_process_primitives` | 在册≠授权（§3.2） | 绿 |
| `exemption_table_entries_are_well_formed` | 理由非空且指向登记处、日期 `YYYY-MM-DD`、无重复条目、原语逐条有说明 | 绿 |

## 4. 单向性证明（变异测试）

"现状全绿"**不等于**闸门有效——它可能只是没扫到。故做了三次真变异（前两次按同一套
`trap` 自动还原，还原后逐字校验）：

| 变异 | 手法 | 期望 | 实测结果 |
| :-- | :-- | :-- | :-- |
| **A：注入未登记的新触网文件** | 新建 `src/gate_mutation_probe.rs`（含 `ureq::get(...).call()`，**不属于任何 mod 声明**，`trap` 退出即删） | 闸门红 | ✅ **红**，并精确报出 `src/gate_mutation_probe.rs:3: [ureq] let resp = ureq::get(url).call().unwrap();`；删除后立即恢复绿；探针文件无残留（`ls` 确认）。**这条同时证明运行时遍历覆盖新文件**——白名单式闸门在此必然漏报 |
| **B：关掉 `#[cfg(test)]` 剔除** | 把 `ranges` 置空后跑主闸门 | 真实测试代码被误报 | ✅ **红** 4 条（`network_gate.rs:955/958/963/964` 的 `"curl"` / `"wget"` fixture）→ 证明"只扫生产代码"这条**是负载的**，不是摆设 |
| **C：去掉 CRLF 归一** | 删掉 `text.replace("\r\n","\n")` 后跑 CRLF 用例 | （预期红） | ⚠️ **仍绿**——见 §2.4：本设计天然抗 CRLF。**这是一条负面结论，如实登记**，并已写进模块注释，避免后人以为"是那行归一把闸门保住了" |

**测试先行的一次真实收益**：§2.2 的 `all(test, unix)` 语义错误是**用例先红**暴露的
（`only_test_only_cfg_items_are_excluded` + `cfg_predicate_evaluation_is_not_substring_matching`

## 6. 已知误报边界与已知豁口（诚实登记）

**误报方向**（会让开发者看到不该看到的红）：

1. `MatchMode::Argv0` 判的是"源码里出现带引号的 `"curl"` / `"wget"`"。若某天真有一条
   **用户文案**恰好就是这两个词（如 `bail!("curl")`），会误报 → 加豁免或改写文案即可，成本低。
2. 指令名以标识符形式出现且与网络无关的场合（`hyper`/`tonic` 作为变量名）——已用词边界 + `::` 限定；
   实测仓内零命中。

**漏报方向**（闸门**拦不住**的，按危害排序）：

1. **`src-tauri/build.rs` 不在扫描面**（任务口径 = `src/**/*.rs`）。实测它当前零网络原语；
   若将来需要，扩面是一行（`source_files()` 加一个根）。
2. **非 Rust 面的网络面**：`tauri.conf.json` 的 `plugins.updater.endpoints`（AGENTS §7 已登记）；
   前端红线（§4.4.2 前端运行时禁止发起新网络请求）由前端 lint/评审管，本闸门不覆盖。
3. **子进程式触网只覆盖 `"curl"` / `"wget"` 两个 argv0 字面量**。其它子进程网络能力
   （`pnpm` / `npm` / `powershell -Command Invoke-WebRequest` / 自建脚本）不在本闸门内——
   它们由 `lifecycle` 的 spawn 闸门 + AGENTS §7 登记 + 人工评审管。这是**刻意画的边界**：
   若把"任何可能触网的子进程"都算网络原语，豁免表会立刻膨胀。
4. **FFI / 动态加载 / 宏展开生成的网络调用**：源码文本判据的原理性上限（同 spawn 闸门）。
5. **`updates.rs` / `updater.rs` / `plugins.rs` 的整文件豁免较宽**：这三个文件内新增一处
   未登记的触网不会被拦。收紧办法是给它们也改用**条目级**豁免（机制已具备，`item: Some("fn 名")`）。
   `boot.rs` 已按条目级处理，可作为收紧模板。
6. **以 `#[cfg(test)] mod X;` 整文件挂载的模块**（今天只有 `network_gate.rs` 自己）：
   扫描器逐文件工作、**不跨文件追踪挂载点**，故这类文件的**模块作用域**会被当作生产代码扫。
   实测今天零命中（原语夹具全在 `#[cfg(test)] mod tests` 内），且失效方向是**可见的误报**
   而非漏扫；已在模块头部写明"夹具必须留在 `mod tests` 内"，并在 §3.4 记录了"自我豁免被
   自检判为死条目"的经过（即：**今天不需要任何自我豁免**）。
   若将来这类模块变多，可在扫描器里加"外部测试模块映射"（本轮刻意不做：为一个当前零命中的
   边界引入跨文件耦合，不划算）。
