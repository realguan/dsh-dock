## 7. 踩过的坑（不踩第二次）

1. **别 `git add -A`**：工作树里长期有**另一个 agent** 的未提交改动——
   `.gitignore`、`README.md`、`docs/CONTRIBUTING.md`、`.cargo/config.toml`、
   `src-tauri/tauri.dev.conf.json`。它们不是本次工作，混进提交即越界（AGENTS §8.5）。
   每次提交都显式列出路径。
2. **`docs/known-issues/` 是 gitignored**（本地登记册），改了不会进提交，别以为丢了。
3. **提交信息写文件再 `git commit -F`**：反引号/`$` 会被 shell 吃掉。
4. **`cargo fmt` 会格式化整个 crate**：若别的 agent 正在改 Rust 源文件，先确认
   `git diff --stat` 只有自己的文件再跑。
5. **`lib/events.ts` 模块加载期就注册 Tauri 监听**（`export const eventBusStarted = initEventBus()`）——
   测试 import 它会因缺 Tauri 运行时失败。纯逻辑请从 `lib/eventPayloads.ts` 取（本轮为此拆出）。
6. **Vitest 读 `?raw` 需要 CSS 开启**：`vite.config.ts` 里 `test: { css: true }` 且用
   `vitest/config` 的 `defineConfig`（否则 `'test' does not exist in type 'UserConfigEntry'`）。
7. **IPC 三处同步**：新命令要同时改 `src-tauri/src/ipc.rs` 的 `COMMANDS`、`lib.rs` 的 handler、
   `capabilities/default.json`；有 cargo test 闸门兜底。结构体形状改 `frontend/src/types/ipc-shapes.json`
   （Rust serde ↔ TS 接口双侧同闸）。
8. **本会话的评审记录做过纠错**：`BootStep.tsx` 当时其实是错的、clipboard 是 11 处不是 10 处、
   `faint` 无法同时满足 4.5 对比度与区分度（已塌成 2 档）。**别照抄评审里的旧描述，以代码为准**
   （AGENTS §8.4 先读后写）。
