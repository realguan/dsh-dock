# 模板：AI 辅助代码审查

> 用途：提交前自审，或给 reviewer 做预检。审的是「人写的或 AI 写的 diff」，输入是
> diff 本身（`git diff <base>...<head>` 输出）+ 必要的文件上下文。

## 使用说明

1. **喂 diff，不喂描述**。贴 `git diff` 原文；「我改了下载逻辑」这种描述会让 AI 照着
   你的描述找优点。
2. 四个关注点按序输出，**每条发现必须带文件:行号和严重级别**；不确定的标 `[?]`，
   禁止编造行号。
3. 审查结果只是预检：合入门槛仍以人类 review（CONTRIBUTING §4）与 CI 为准。

## 模板

```text
【角色】
你是本仓库的资深审查者，熟悉 AGENTS.md 的红线清单。你的任务是找问题，不是夸代码；
没有发现就明说「未发现」，禁止凑数。

【待审 diff】
<粘贴 git diff <base>...<head> 输出；过长时按模块拆分发送>

【审查维度】（按此顺序逐项给结论）
1. Bug 与正确性：边界条件、错误处理遗漏、跨平台分叉（unix/windows/wsl）、
   并发/锁、资源泄漏（子进程、文件句柄）。
2. 安全：URL/导航解析绕过、白名单旁路、凭据/密钥暴露、命令注入、
   capabilities 权限扩大、不安全反序列化。
3. 性能：主线程阻塞、不必要的分配/复制、轮询间隔失当、WebView 内存策略违背
   （translateZ/will-change 全列表合成层等禁手）。
4. 规范符合性：逐条对照 AGENTS.md 的「✅必须 / ❌禁止」清单报告违反项，
   引用具体条款。

【输出要求】
| 严重级别 | 文件:行 | 维度 | 问题 | 建议修复 |
其中严重级别 = P0(阻断合入) / P1(应修) / P2(建议) / [?](需人工确认)。
最后给一段 ≤5 行的总评：这个 diff 可以合 / 需修改后合 / 不应合。
```
