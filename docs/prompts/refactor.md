# 模板：受限重构

> 用途：改结构不改行为。重构是最容易失控的场景——AI 天生爱「顺便优化」，
> 本模板的全部重点在**围栏**上。

## 使用说明

1. 「行为不变」必须落到可验证的锚点：**现有测试一个不许删、断言一个不许改**
   （允许为私有函数改名而同步更新调用点）。
2. 量化边界：行数预算、文件白名单、禁止清单，三样都要有。模糊的「小步重构」
   等于没有约束。
3. 涉及公共模块（`docs/contracts/` 列名者）先读对应契约——重构不得改变契约面，
   否则走契约变更流程而不是本模板。

## 模板

```text
【角色】
你是本仓库的重构执行者。铁律：**行为不变**。你唯一的自由度是内部结构；
任何行为变化（哪怕看起来是修复）都算越界。

【重构目标】
<要消除的具体问题，如：updates.rs 中 Node 下载与 dsh 安装逻辑耦合，
无法单测续传起点计算>
<理想形态，如：抽出纯函数 download_plan(...) 可独立测试>

【硬性围栏】
- 文件白名单：<精确路径清单>；白名单外只读。
- 行数预算：净增 ≤ <N> 行；删除多于新增为宜。
- 禁止事项：
  * 不改任何公开/IPC 接口签名与事件 payload；
  * 不引入新依赖、新模块文件（拆分仅限白名单内部）；
  * 不做「顺手」修复/优化/重命名——发现的问题写进报告，不动手；
  * 不动 #[cfg(test)] 内既有断言语义。
- 验证锚点：cd src-tauri && cargo test 全绿且测试数量不减。

【输出要求】
1. 先列重构步骤清单（每步独立可编译、可跑测），等我确认；
2. 分步输出 diff，每步附 cargo test 结果说明；
3. 结束时输出报告：实际改动统计（+x/-y）、白名单符合性自查、
   过程中发现但未动手的问题清单。
```

## 已填示例（节选）

```text
【重构目标】
resolve.rs 宿主解析链三段（system/bundle/download）各自内联版本比较，
同一 semver 判等逻辑抄了四处 → 抽出纯函数 version_satisfies(...)。

【硬性围栏】
- 白名单：src-tauri/src/resolve.rs 单文件。
- 行数预算：净增 ≤ 30 行（预期负增长）。
- 验证锚点：cargo test 全绿，resolve 的 14 个既有测试原样通过。

—— 报告片段：
实际 +18/-52；白名单符合 ✅；未动手问题清单：
1) resolve.rs:207 错误文案硬编码英文（P2，建议另行修复）
2) resolve.rs 与 updates.rs 存在第二处重复（超白名单，建议下次专项）
```
