# 模板：新功能实现

> 用途：把一句需求变成结构化的 AI 任务。填完所有空位再发送。

## 使用说明

1. 「验收标准」必须写成**可执行的检查项**（能跑命令、能看到现象），不写形容词。
2. 「技术约束」从 AGENTS.md 抄相关红线，别凭记忆写——AI 不会自己去查。
3. 若功能涉及新 IPC 命令，在约束里点名「三处同步」（lib.rs + build.rs + capabilities）。
4. 输出要求里强制「先方案后代码」，避免 AI 直接糊一屏改动。

## 模板

```text
【角色】
你是本仓库的资深 Rust/Tauri 工程师，严格遵守根目录 AGENTS.md 的全部约束。
动任何文件前先读它的现状。

【需求描述】
<一句话说清要做什么、给谁用、解决什么问题>
<背景/动机，为什么现在做>

【技术约束】
- 允许改动的文件：<精确路径或模块清单>；其余文件只读。
- 必须遵守：<从 AGENTS.md 抄与本任务相关的红线，
  如：Windows 子进程经 crate::child_cmd；网络只在 updates.rs；UI 零构建器；
  禁止 unwrap 于库路径；日志用 tracing>
- 禁止顺手重构无关代码；发现相邻问题记入「后续建议」，不要动手。

【验收标准】
- [ ] <可执行检查 1，如：cd src-tauri && cargo test 全绿>
- [ ] <行为检查 2，如：macOS cargo run 后首次启动出现模式选择页>
- [ ] <回归检查 3，如：既有 X 行为不变（列出验证方法）>

【输出要求】
1. 先给出实施方案（≤10 行：动哪些文件、新增什么函数/事件、风险点），等我确认；
2. 确认后再输出完整代码变更（不要省略号截断）；
3. 每个新函数附带单元测试（参照 shell.rs / manifest.rs 先例）；
4. 最后附一段 commit message 草稿（type(scope): 中文描述 + AI-Assisted 标注）。
```

## 已填示例（节选）

```text
【需求描述】
启动页增加 Node 下载的暂停/恢复按钮。给慢网络用户，避免 40MB 下载失败后从头再来。

【技术约束】
- 允许改动：src-tauri/src/updates.rs（下载循环）、ui/index.html（按钮与状态）、
  lib.rs（桥接事件）；其余只读。
- 必须遵守：下载已在后台线程；进度节流 ≥100ms 不得破坏；
  boot:progress 事件 payload 结构不得变更（前端兼容）。

【验收标准】
- [ ] cargo test 全绿，含新增「恢复后 Range 续传起点正确」单测
- [ ] 断网点恢复 → 下载从已收字节数继续（看 dsh-shell.log）
```
